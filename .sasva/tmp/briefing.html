★ At a glance

What this is

Gitea — a large, mature self-hosted Git platform. Go 1.26 layered-monolith backend (routers → services → models → modules) paired with a Vue 3 / TypeScript frontend built on Vite & TailwindCSS.

Enforcement, not discipline

Architecture and style rules are enforced by tooling — depguard, golangci-lint, ESLint (flat config + a dedicated JSON linter), and Stylelint — rather than left to reviewer memory.

Confidence split

Frontend tooling configs and two Go entrypoint files were directly verified this pass. Deeper backend claims (ORM exclusivity, migration depguard rules, LDAP, goldmark) are carried forward, unverified-but-uncontradicted.

Hard constraints

Mandatory gitea.dev/modules/json (never encoding/json), mandatory Assisted-by trailer on AI commits, and a CI-breaking forbidden-import list enforced via depguard.

Key items to verify or watch

  • ORM exclusivity: confirm no raw database/sql usage anywhere in models/ — claim is carried forward, not re-checked.
  • Migration depguard rule: inspect .golangci.yml directly to confirm migrations truly cannot import models/modules/structs.
  • Markdown engine: verify goldmark is the only renderer — no competing library sneaking in via a transitive dependency.
  • LDAP surface: review cmd/admin_auth_ldap*.go first-hand before treating LDAP as fully core.
  • Layering discipline in practice: trace one real feature (e.g. issues or actions) end-to-end through models → services → routers to confirm the layering holds, not just the docs.
  • Forbidden imports: any PR introducing encoding/json, io/ioutil, pkg/errors, or gopkg.in/ini.v1 will fail CI via depguard — catch this in review, not just CI.
  • AI commit trailers: Co-Authored-By / Signed-off-by are explicitly forbidden for AI contributions — use Assisted-by: AGENT_NAME:MODEL_VERSION instead.
