<h1>Access Tokens & OAuth2 Applications</h1>
<h1 id="access-tokens-oauth2-applications">Access Tokens &amp; OAuth2 Applications</h1>
<p>Gitea issues and validates two kinds of bearer credential: <strong>Personal Access Tokens (PATs)</strong> —
long-lived tokens a user creates for themselves — and <strong>OAuth2 access/refresh/ID tokens</strong> —
issued through a full OAuth2 Authorization Code (+ PKCE) flow to a registered
<code>OAuth2Application</code>, where Gitea itself acts as the <strong>OAuth2/OpenID Connect provider</strong>. This page
documents both, re-verified against
<a href="../../services/oauth2_provider"><code>services/oauth2_provider</code></a>,
<a href="../../models/auth/oauth2.go"><code>models/auth/oauth2.go</code></a>,
<a href="../../models/auth/access_token.go"><code>models/auth/access_token.go</code></a>/<code>access_token_scope.go</code>, and
the route handlers in <a href="../../routers/web/auth/oauth2_provider.go"><code>routers/web/auth/oauth2_provider.go</code></a>.</p>
<blockquote>
<p>This is the <em>provider</em> side of OAuth2 (Gitea issuing tokens to third-party apps). For Gitea
acting as an OAuth2 <em>client</em> against an external IdP (login via GitHub/Google/etc.), see
<a href="auth-sources.html#oauth2--openid-connect-servicesauthsourceoauth2">Authentication Sources</a>.</p>
</blockquote>
<h2 id="personal-access-tokens-pats">Personal Access Tokens (PATs)<a href="#personal-access-tokens-pats" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Modeled by <code>AccessToken</code> in <a href="../../models/auth/access_token.go"><code>models/auth/access_token.go</code></a>:</p>
<pre class="highlight"><code class="language-go">type AccessToken struct {
    ID             int64 `xorm:"pk autoincr"`
    UID            int64 `xorm:"INDEX"`
    Name           string
    Token          string `xorm:"-"`            // only available at creation time
    TokenHash      string `xorm:"UNIQUE"`        // sha256+salt of token, persisted
    TokenSalt      string
    TokenLastEight string `xorm:"INDEX token_last_eight"` // fast index lookup
    Scope          AccessTokenScope

    CreatedUnix       timeutil.TimeStamp `xorm:"INDEX created"`
    UpdatedUnix       timeutil.TimeStamp `xorm:"INDEX updated"`
    HasRecentActivity bool               `xorm:"-"` // derived: used within last 7 days
    HasUsed           bool               `xorm:"-"` // derived: UpdatedUnix &gt; CreatedUnix
}</code></pre>
<p>Tokens are <strong>never stored in plaintext</strong>. <code>NewAccessToken</code> generates 20 random bytes
(<code>util.CryptoRandomBytes</code>), hex-encodes them as the plaintext token, and stores only:</p>
<ul>
<li><code>TokenLastEight</code> — the last 8 hex characters, used purely as a fast pre-filter index (not a
  security boundary).</li>
<li><code>TokenHash</code> — <code>HashToken(token, salt)</code>, a PBKDF2-SHA256 hash (10,000 iterations, 50-byte
  output, defined in <code>models/auth/twofactor.go</code>'s shared <code>HashToken</code> helper) with a random
  per-token <code>TokenSalt</code>.</li>
</ul>
<p><code>GetAccessTokenBySHA(ctx, token)</code> looks up candidates by <code>TokenLastEight</code>, then does a
constant-time comparison (<code>crypto/subtle.ConstantTimeCompare</code>) of the computed hash against each
candidate's <code>TokenHash</code> — this defeats timing attacks that might otherwise leak the hash byte by
byte. An optional LRU cache (<code>successfulAccessTokenCache</code>, sized by
<code>setting.SuccessfulTokensCacheSize</code>) short-circuits repeated hashing for hot tokens by caching
<code>token → id</code>, re-verifying existence against the DB on each hit (so a deleted token is evicted
lazily rather than trusted from cache indefinitely).</p>

<ul>
<li><strong><code>AccessTokenScopePublicOnly</code></strong> further restricts a token to public repositories/organizations
  <em>regardless</em> of what other scopes it was granted — enforced explicitly, e.g. in the packages

  public-only tokens. <code>Scope.PublicOnly()</code> checks for this bit; <code>AccessToken.DisplayPublicOnly()</code>
  surfaces it for the settings UI.</li>
<li><strong>Empty/absent scope defaults to <code>all</code></strong> — since Gitea 1.22, a PAT with no explicit scope
  string grants full API access, matching pre-scope-system behavior; scoping down is opt-in.</li>
<li><strong><code>Scope.Normalize()</code></strong> deduplicates and canonicalizes a raw comma-joined scope string,
  rejecting unrecognized scope names.</li>
</ul>
<h3 id="scope-enforcement-points">Scope Enforcement Points<a href="#scope-enforcement-points" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Two independent checks are combined for any token-authenticated request:</p>
<ol>
<li><strong>Route/endpoint scope requirement</strong> — API route middlewares (<code>reqToken</code>/<code>tokenRequiresScopes</code>
   in <code>routers/api/v1</code>, and the packages API's own <code>tokenRequiresScope</code>) check whether the
   resolved scope (from <code>GetAccessScope(store)</code> for PATs, or <code>grant.Scope</code> for OAuth2 tokens)
   contains the category/verb the endpoint declares it needs.</li>
<li><strong>Resource-level <code>Permission</code>/<code>AccessMode</code></strong> — see
   <a href="authorization-model.html">Authorization Model</a> — scope never <em>grants</em> access to a resource the
   underlying user account itself cannot access; it can only <em>further restrict</em> what an
   otherwise-permitted user's credential may be used for.</li>
</ol>
<p><code>GetAccessScope(store)</code> (in <code>services/auth</code>) derives the effective scope for the current request:
Basic/session logins get <code>AccessTokenScopeAll</code> (no additional restriction beyond the account's
own permissions), Actions task tokens get no general API scope (enforced through a completely
separate Actions-specific permission path — see
<a href="authorization-model.html#actions-bot-permission-getactionsuserrepopermission">Authorization Model</a>),
and PAT/OAuth2-token requests get the token's/grant's own scope.</p>
<h2 id="oauth2-applications-gitea-as-a-provider">OAuth2 Applications — Gitea as a Provider<a href="#oauth2-applications-gitea-as-a-provider" class="heading-anchor" aria-label="Link">#</a></h2>
<p><a href="../../models/auth/oauth2.go"><code>models/auth/oauth2.go</code></a> models the RFC 6749 client:</p>
<pre class="highlight"><code class="language-go">type OAuth2Application struct {
    ID           int64 `xorm:"pk autoincr"`

<ul>
<li><strong><code>ConfidentialClient</code></strong> distinguishes RFC 6749 §2.1 client types — public clients (e.g. CLI
  tools, mobile apps) that cannot keep a secret must instead use <strong>PKCE</strong> (see below).</li>
<li><strong><code>SkipSecondaryAuthorization</code></strong> lets a trusted first-party app (e.g. Gitea's own official
  integrations) skip the "Authorize this application?" consent screen on repeat logins.</li>
<li><strong>Builtin applications</strong> — <code>BuiltinApplications()</code> hardcodes fixed <code>ClientID</code>s for

  <code>setting.OAuth2.DefaultApplications</code> on startup — adding, and removing, builtin app rows to
  match the configured list without touching user-created <code>OAuth2Application</code>s.</li>
</ul>
<h3 id="authorization-code-flow-with-pkce">Authorization Code Flow with PKCE<a href="#authorization-code-flow-with-pkce" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>OAuth2AuthorizationCode</code> (short-lived, 10-minute validity per RFC 6749 §4.1.2) is generated by
<code>OAuth2Grant.GenerateNewAuthorizationCode(ctx, redirectURI, codeChallenge, codeChallengeMethod)</code>
and stores the PKCE challenge alongside the code:</p>
<pre class="highlight"><code class="language-go">type OAuth2AuthorizationCode struct {
    Grant               *OAuth2Grant
    Code                string `xorm:"INDEX unique"`
    RedirectURI         string
    ValidUntil          timeutil.TimeStamp
    CodeChallenge       string
    CodeChallengeMethod string
}</code></pre>
<p><code>requiresCodeVerifier()</code> reports whether a <code>code_verifier</code> must be presented at the token
exchange step. <code>ValidateCodeChallenge(verifier)</code> recomputes the expected challenge via
<code>deriveCodeChallenge(method, verifier)</code> (supporting <code>S256</code> — SHA-256 then base64url — and
<code>plain</code>) and compares it to the stored <code>CodeChallenge</code> with <code>crypto/subtle.ConstantTimeCompare</code>.
<code>Invalidate(ctx)</code> deletes the code row once consumed, and any attempt to redeem an already-used
code returns <code>ErrOAuth2AuthorizationCodeInvalidated</code>.</p>
<p><code>AuthorizeOAuth</code> (<code>routers/web/auth/oauth2_provider.go</code>) — the <code>/login/oauth/authorize</code> handler —
enforces PKCE server-side:</p>
<ul>
<li><code>CodeChallengeMethod</code> of <code>S256</code> or <code>plain</code> is accepted and stashed in the session.</li>
<li>An <strong>empty</strong> <code>CodeChallengeMethod</code> is only permitted for <code>ConfidentialClient</code> apps — RFC 8252
  §8.1/RFC 7636 §4.4.1 require public (non-confidential) clients to use PKCE, so this path
  returns <code>invalid_request</code> for a public client that omits it.</li>
<li>Any other value is rejected as <code>invalid_request</code> ("unsupported code challenge method").</li>
</ul>
<p>If the user already granted this application access (<code>app.GetGrantByUserID</code>) and the app is
confidential or has <code>SkipSecondaryAuthorization</code>, a new code is minted and the browser is
redirected immediately — otherwise the consent (<code>tplGrantAccess</code>) page is shown, and
<code>GrantApplicationOAuth</code> handles the user's approval POST.</p>
<pre class="mermaid">sequenceDiagram
    participant U as User (browser)
    participant G as Gitea (/login/oauth/authorize)

    App->>U: Redirect to /login/oauth/authorize?client_id=...&code_challenge=...&response_type=code

<h3 id="token-issuance-servicesoauth2_provider">Token Issuance (<code>services/oauth2_provider</code>)<a href="#token-issuance-servicesoauth2_provider" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>NewAccessTokenResponse(ctx, grant, serverKey, clientKey)</code> in
<a href="../../services/oauth2_provider/access_token.go"><code>services/oauth2_provider/access_token.go</code></a>
issues the actual tokens once a code (or refresh token) has been validated by
<code>handleAuthorizationCode</code>/<code>handleRefreshToken</code> in <code>routers/web/auth/oauth2_provider.go</code>:</p>
<ul>
<li><strong>Access token</strong> — a signed JWT <code>Token{GrantID, Kind: KindAccessToken, RegisteredClaims{ExpiresAt}}</code>
  with lifetime <code>setting.OAuth2.AccessTokenExpirationTime</code>.</li>
<li><strong>Refresh token</strong> — <code>Token{GrantID, Counter, Kind: KindRefreshToken}</code>; <code>Counter</code> is copied from
  the grant's current counter. If <code>setting.OAuth2.InvalidateRefreshTokens</code> is enabled,
  <code>grant.IncreaseCounter(ctx)</code> bumps the grant's counter on every access-token issuance, and a
  refresh token presenting a stale counter is rejected — this makes each refresh token
  effectively single-use, detecting token theft/replay
  (<code>ErrOAuth2GrantStaleCounter</code>).</li>
<li><strong>ID token</strong> (OpenID Connect) — only when the grant's scope contains <code>openid</code>. <code>OIDCToken</code>
  (<code>services/oauth2_provider/token.go</code>) embeds standard claims plus optional <code>profile</code>/<code>email</code>/
  <code>groups</code> claims, populated only if those respective scopes were also granted. The <code>groups</code>
  claim is populated by <code>GetOAuthGroupsForUser</code>, which returns <code>"&lt;org&gt;"</code> and <code>"&lt;org&gt;:&lt;team&gt;"</code>
  strings for every organization/team the user belongs to (restricted to public organizations
  only if the token's <code>AccessTokenScope</code> includes <code>public-only</code>).</li>
</ul>
<p>Both <code>Token</code> and <code>OIDCToken</code> are signed JWTs (<code>github.com/golang-jwt/jwt/v5</code>) using a
<code>JWTSigningKey</code> abstraction (<code>services/oauth2_provider/jwtsigningkey.go</code>) supporting HMAC
(symmetric, for opaque access/refresh tokens) and RSA/ECDSA/EdDSA (asymmetric, for OIDC ID
tokens verifiable by third parties via the <code>/login/oauth/keys</code> JWKS endpoint —
<code>OIDCKeys</code> handler — built from <code>ToJWK()</code> on each key type).</p>
<p><code>GrantAdditionalScopes(grantScopes string)</code> filters the raw space-separated OIDC scope string
down to only the scopes that map to Gitea's <code>AccessTokenScope</code> categories (dropping the
"general information" scopes <code>openid</code>/<code>profile</code>/<code>email</code>/<code>groups</code>, which control ID-token claim
content rather than API access) — an empty result after filtering means unrestricted (<code>all</code>)
access, matching PAT scope defaults.</p>
<h3 id="oauth2grant-the-persisted-consent-record"><code>OAuth2Grant</code> — the Persisted Consent Record<a href="#oauth2grant-the-persisted-consent-record" class="heading-anchor" aria-label="Link">#</a></h3>
<pre class="highlight"><code class="language-go">func (grant *OAuth2Grant) ScopeContains(scope string) bool

<p>One <code>OAuth2Grant</code> row exists per <code>(application, user)</code> pair, recording the granted <code>Scope</code>

grants (and can <code>RevokeOAuth2Grant</code>) from account security settings; revoking immediately
invalidates all access/refresh tokens tied to that grant since token validation re-loads the
grant by ID on every use.</p>

      for(var n=0;n<Math.min(mh.length,2);n++){html+='<div class="search-heading">↳ '+mh[n]+'</div>';}
    }
    if(!hits.length)html='<div style="padding:8px 12px;color:var(--text-dim);font-size:0.8rem">No results</div>';
    searchResults.innerHTML=html;
  });

<script>
(function(){
  // Mermaid expand buttons — added AFTER mermaid renders (so button is on wrapper, not inside pre)
  var overlay=document.getElementById('mermaid-overlay');
  var overlayInner=document.getElementById('mermaid-overlay-inner');
  function _addMermaidButtons(){
    document.querySelectorAll('.mermaid,pre.mermaid').forEach(function(el){
      if(el.dataset.expandAdded)return;
      el.dataset.expandAdded='1';
      // Wrap in a div so the button is a sibling of pre, not inside it
      var wrapper=document.createElement('div');
      wrapper.style.cssText='position:relative;display:inline-block;width:100%;';
      el.parentNode.insertBefore(wrapper,el);
      wrapper.appendChild(el);
      var btn=document.createElement('button');
      btn.className='mermaid-expand';btn.textContent='⛶';btn.title='Expand diagram';
      btn.addEventListener('click',function(e){
        e.stopPropagation();
        var clone=el.cloneNode(true);
        delete clone.dataset.expandAdded;
        clone.removeAttribute('data-expand-added');
        clone.style.cssText='background:none;border:none;padding:0;margin:0;text-align:center;min-width:70vw;max-width:90vw;';
        // Clear overlay content safely, keep close button
        overlayInner.innerHTML='';
        var closeBtn=document.createElement('button');
        closeBtn.className='mermaid-overlay-close';closeBtn.textContent='×';closeBtn.title='Close';
        closeBtn.addEventListener('click',function(){overlay.classList.remove('open');});
        overlayInner.appendChild(clone);
        overlayInner.appendChild(closeBtn);
        overlay.classList.add('open');
        // Re-run mermaid on the clone after it's in the DOM
        setTimeout(function(){
          if(window.mermaid){
            try{mermaid.run({nodes:[clone]});}catch(err){}
          }
        },50);
      });
      wrapper.appendChild(btn);
    });
  }
  // Wait for mermaid to finish rendering before adding buttons (mermaid init runs above)
  setTimeout(_addMermaidButtons,800);
  if(overlay){
    overlay.addEventListener('click',function(e){if(e.target===overlay)overlay.classList.remove('open');});
    document.addEventListener('keydown',function(e){if(e.key==='Escape')overlay.classList.remove('open');});
  }
  // Code copy buttons
  document.querySelectorAll('pre').forEach(function(pre){
    if(pre.classList.contains('mermaid'))return;
    var btn=document.createElement('button');
    btn.className='code-copy';btn.textContent='Copy';
    btn.addEventListener('click',function(){
      var code=pre.querySelector('code');
      var text=code?code.textContent:pre.textContent;
      navigator.clipboard.writeText(text).then(function(){btn.textContent='Copied!';setTimeout(function(){btn.textContent='Copy';},2000);});
    });
    pre.appendChild(btn);
  });
  // Back to top
  var btt=document.getElementById('back-to-top');
  if(btt){
    window.addEventListener('scroll',function(){btt.style.display=window.scrollY>300?'flex':'none';});
    btt.addEventListener('click',function(){window.scrollTo({top:0,behavior:'smooth'});});
  }
  // TOC active scroll tracking
  var tocLinks=document.querySelectorAll('.toc-aside a[data-anchor]');
  if(tocLinks.length>0){
    var headingEls=[];
    tocLinks.forEach(function(l){var el=document.getElementById(l.dataset.anchor);if(el)headingEls.push({el:el,link:l});});
    var tocAside=document.querySelector('.toc-aside');
    var onScroll=function(){
      var scrollPos=window.scrollY+80;
      var active=null;
      for(var i=0;i<headingEls.length;i++){if(headingEls[i].el.offsetTop<=scrollPos)active=headingEls[i];}
      tocLinks.forEach(function(l){l.classList.remove('toc-active');});
      if(active){
        active.link.classList.add('toc-active');
        // Scroll active link into view within the TOC panel, not the page
        if(tocAside){
          var linkTop=active.link.offsetTop-tocAside.offsetTop;
          var visibleTop=tocAside.scrollTop;
          var visibleBottom=visibleTop+tocAside.clientHeight;
          if(linkTop<visibleTop+40||linkTop>visibleBottom-40){
            tocAside.scrollTop=linkTop-tocAside.clientHeight/2;
          }
        }
      }
    };
    window.addEventListener('scroll',onScroll);
    onScroll();
    // Prevent TOC links from scrolling the TOC panel to top on click
    tocLinks.forEach(function(l){
      l.addEventListener('click',function(e){
        e.preventDefault();
        var anchor=l.dataset.anchor;
        var target=document.getElementById(anchor);
        if(target){target.scrollIntoView({behavior:'smooth',block:'start'});}
      });
    });
  }
  // Persist sidebar scroll position across page navigations
  var sidebarEl=document.querySelector('nav.sidebar');
  if(sidebarEl){
    var sidebarKey='sasva-sidebar-scroll';
    // Restore scroll position on page load
    var savedScroll=sessionStorage.getItem(sidebarKey);
    if(savedScroll){sidebarEl.scrollTop=parseInt(savedScroll,10);}
    // Save scroll position before navigating away
    document.querySelectorAll('#sidebar-nav-links a').forEach(function(a){
      a.addEventListener('click',function(){
        sessionStorage.setItem(sidebarKey,String(sidebarEl.scrollTop));
      });
    });
    // Also scroll active item into view on load
    var activeLink=sidebarEl.querySelector('a.active');
    if(activeLink&&!savedScroll){
      var linkOffset=activeLink.offsetTop-sidebarEl.offsetTop;
      sidebarEl.scrollTop=Math.max(0,linkOffset-sidebarEl.clientHeight/2);
    }
  }
})();
