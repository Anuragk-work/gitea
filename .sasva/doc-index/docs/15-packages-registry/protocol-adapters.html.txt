<h1>Protocol Adapters</h1>
<h1 id="protocol-adapters">Protocol Adapters</h1>
<p>Every one of the <a href="supported-ecosystems.html">22+ package ecosystems</a> shares the same five
database tables (<a href="database-schema.html">Database Schema</a>) and the same low-level storage/hashing
primitives (<a href="shared-infrastructure.html">Shared Infrastructure</a>). What actually differs between
<code>npm publish</code>, <code>cargo publish</code>, <code>docker push</code>, and <code>apt-get install</code> is the <strong>wire protocol</strong> —
the specific HTTP paths, request/response bodies, and index-file formats each native client
already expects. This page documents the adapter layer that translates each of those protocols
into calls against the shared services/models, and calls out the ecosystems that need
additional service-layer machinery beyond a simple upload/download.</p>
<blockquote>
<p>For the full route-by-route endpoint reference (HTTP verbs, paths, and auth), see
<a href="../07-rest-api/packages-and-actions-api.html#packages-registry-api-routersapipackages">Packages &amp; Actions API</a>
in the REST API section — this page focuses on <em>how the adapters are implemented</em>, not on
enumerating every path.</p>
</blockquote>
<h2 id="anatomy-of-an-adapter">Anatomy of an Adapter<a href="#anatomy-of-an-adapter" class="heading-anchor" aria-label="Link">#</a></h2>
<p>A protocol adapter is composed of up to three packages that mirror the general
<a href="../08-services/README.html">Services</a> / <a href="../06-web-routers/README.html">Web Routers</a> split used
throughout Gitea:</p>
<table>
<thead>
<tr>
<th>Layer</th>
<th>Package</th>
<th>Responsibility</th>
</tr>
</thead>
<tbody>
<tr>
<td>Router</td>
<td><code>routers/api/packages/&lt;type&gt;</code></td>
<td>Speaks the wire protocol: parses the ecosystem's specific request shape (multipart form, JSON body, OData/Atom XML, sparse-index paths, ...), writes the expected response shape</td>
</tr>
<tr>
<td>Module</td>
<td><code>modules/packages/&lt;type&gt;</code></td>
<td>Pure, HTTP/DB-free functions that parse the ecosystem's archive/metadata format (<code>ParsePackage</code>, <code>ParsePackageMetaData</code>, <code>ParseManifestMetadata</code>, ...) and validate names/versions</td>
</tr>
<tr>
<td>Service</td>
<td><code>services/packages/&lt;type&gt;</code> (only for ecosystems that need index/repository regeneration or signing — see below)</td>
<td>Orchestrates multi-file index rebuilds, GPG signing, and other stateful operations too heavyweight for a router handler</td>
</tr>
</tbody>
</table>
<p>Simple ecosystems (npm, PyPI, Maven, RubyGems, Generic, Composer, CRAN, Chef, Pub, Swift,
Vagrant, Go proxy) only need the first two layers — their router handlers call straight into
the shared <code>services/packages/packages.go</code> helpers (<code>CreatePackageAndAddFile</code>,
<code>AddFileToExistingPackage</code>, <code>OpenFileForDownload</code>, ...) documented in
<a href="package-flow.html">Package Upload/Download Flow</a>. Ecosystems whose <em>native protocol</em> requires
Gitea to generate and serve a repository-wide index (Alpine, Arch, Debian, RPM, Cargo) or to

<h2 id="index-rebuilding-adapters">Index-Rebuilding Adapters<a href="#index-rebuilding-adapters" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Alpine, Arch, Debian, RPM, and Cargo don't just store an uploaded file — their native clients
expect to <code>GET</code> a <strong>repository-wide index</strong> (an <code>APKINDEX.tar.gz</code>, a <code>packages.db</code>, a
<code>Packages</code>/<code>Release</code> file set, a <code>repodata/</code> directory, or a Cargo sparse-index JSON-lines
file) that lists every package currently published under that owner. Gitea builds these index
files on the fly and stores them as the files of a single <strong>internal, hidden package version</strong>
(<code>PackageVersion.IsInternal = true</code>) created via the shared
<code>services/packages.GetOrCreateInternalPackageVersion</code> helper — reusing the exact same
<code>Package</code>/<code>PackageVersion</code>/<code>PackageFile</code>/<code>PackageBlob</code> tables as any other package, just marked
so it never shows up in the package list UI.</p>
<h3 id="common-shape-getorcreaterepositoryversion-buildallrepositoryfiles-buildspecificrepositoryfiles">Common shape: <code>GetOrCreateRepositoryVersion</code> / <code>BuildAllRepositoryFiles</code> / <code>BuildSpecificRepositoryFiles</code><a href="#common-shape-getorcreaterepositoryversion-buildallrepositoryfiles-buildspecificrepositoryfiles" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Alpine (<code>services/packages/alpine/repository.go</code>), Debian (<code>services/packages/debian/repository.go</code>),
RPM (<code>services/packages/rpm/repository.go</code>), and Arch (<code>services/packages/arch/repository.go</code>)
all expose the same three-function pattern:</p>
<pre class="highlight"><code class="language-go">// GetOrCreateRepositoryVersion gets or creates the internal repository package
func GetOrCreateRepositoryVersion(ctx context.Context, ownerID int64) (*packages_model.PackageVersion, error) {
    return packages_service.GetOrCreateInternalPackageVersion(ctx, ownerID, packages_model.TypeDebian,
        debian_module.RepositoryPackage, debian_module.RepositoryVersion)
}

// BuildAllRepositoryFiles (re)builds all repository files for every available distributions,
// components and architectures
func BuildAllRepositoryFiles(ctx context.Context, ownerID int64) error { ... }

// BuildSpecificRepositoryFiles builds index files for one distribution/component/architecture
// (or one repository/architecture for Alpine/Arch, one repo group for RPM) — called after a
// single upload/delete instead of rebuilding everything
func BuildSpecificRepositoryFiles(ctx context.Context, ownerID int64, /* ecosystem-specific dims */) error { ... }</code></pre>
<p><code>BuildAllRepositoryFiles</code> is invoked from the CLI/admin <code>doctor</code>-style regeneration paths and
after settings changes; <code>BuildSpecificRepositoryFiles</code> is invoked by the router handler
immediately after a package upload or delete so the index reflects the change without a full
rebuild of every distribution/architecture combination.</p>
<p>Each rebuild follows the same three steps, illustrated here with Debian's
<code>buildRepositoryFiles</code>:</p>
<ol>
<li><strong>Delete stale index files</strong> for the given dimension key (e.g.
   <code>distribution|component|architecture</code> for Debian, or the repository/architecture pair for
   Alpine/Arch) if there are no packages left matching it.</li>
<li><strong>Stream-generate the index</strong> using a <code>packages_module.HashedBuffer</code> fanned out through
   <code>io.MultiWriter</code> to multiple compressed encodings simultaneously — Debian writes plain,
   gzip, <em>and</em> xz variants of <code>Packages</code> in a single pass over the package list:</li>
</ol>
<pre class="highlight"><code class="language-go">packagesContent, _ := packages_module.NewHashedBuffer()
packagesGzipContent, _ := packages_module.NewHashedBuffer()
gzw := gzip.NewWriter(packagesGzipContent)
packagesXzContent, _ := packages_module.NewHashedBuffer()
xzw, _ := xz.NewWriter(packagesXzContent)
w := io.MultiWriter(packagesContent, gzw, xzw)
// ... write each package's Debian control stanza + Filename/Size/checksums to w ...</code></pre>
<ol>
<li><strong>Persist as files on the internal version</strong> via
   <code>packages_service.AddFileToPackageVersionInternal</code>, with <code>OverwriteExisting: true</code> so a
   rebuild replaces the previous index file's blob rather than erroring on
   <code>ErrDuplicatePackageFile</code>.</li>
</ol>
<h3 id="repository-signing-gpg">Repository signing (GPG)<a href="#repository-signing-gpg" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Alpine, Arch, Debian, and RPM repositories are consumed by clients (<code>apk</code>, <code>pacman</code>, <code>apt</code>,
<code>dnf</code>/<code>yum</code>) that verify a <strong>detached or clearsigned GPG signature</strong> over the index before
trusting it. All four ecosystems implement the identical <code>GetOrCreateKeyPair</code> pattern:</p>
<pre class="highlight"><code class="language-go">// GetOrCreateKeyPair gets or creates the PGP keys used to sign repository files
func GetOrCreateKeyPair(ctx context.Context, ownerID int64) (string, string, error) {
    priv, err := user_model.GetSetting(ctx, ownerID, debian_module.SettingKeyPrivate)
    pub, err := user_model.GetSetting(ctx, ownerID, debian_module.SettingKeyPublic)
    if priv == "" || pub == "" {
        priv, pub, err = generateKeypair() // openpgp.NewEntity + armor.Encode
        user_model.SetUserSetting(ctx, ownerID, debian_module.SettingKeyPrivate, priv)
        user_model.SetUserSetting(ctx, ownerID, debian_module.SettingKeyPublic, pub)
    }
    return priv, pub, nil
}</code></pre>
<p>The keypair is generated once per owner (user or organization) on first use via
<code>github.com/ProtonMail/go-crypto/openpgp</code>, stored as user settings (<code>SettingKeyPrivate</code> /
<code>SettingKeyPublic</code>, per-ecosystem setting keys so a single owner can have independent Alpine,
Arch, Debian, and RPM signing keys), and never rotated automatically. The <strong>public</strong> key is
served back to clients at a well-known repo path (e.g. <code>GET /alpine/key</code>, <code>GET
/arch/repository.key</code>) so they can trust future signed indices; the router layer, not the
service layer, exposes that endpoint.</p>
<p>Debian additionally produces three signed artifacts per distribution — <code>Release</code> (plain),
<code>Release.gpg</code> (detached signature via <code>openpgp.ArmoredDetachSign</code>), and <code>InRelease</code>
(clearsigned via <code>openpgp.clearsign.Encode</code>) — matching the <a href="https://wiki.debian.org/DebianRepository/Format#A.22Release.22_files">Debian repository
format</a> so both older
<code>apt</code> (which wants a separate <code>.gpg</code> file) and newer <code>apt</code> (which prefers the single
clearsigned <code>InRelease</code>) are satisfied by the same rebuild pass. RPM signs its <code>repomd.xml</code>
similarly; Arch signs each per-architecture <code>packages.db</code> archive.</p>
<h3 id="cargo-sparse-index-over-a-git-repository-not-a-flat-file">Cargo: sparse index over a Git repository, not a flat file<a href="#cargo-sparse-index-over-a-git-repository-not-a-flat-file" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Cargo is the one index-building ecosystem that does <strong>not</strong> store its index as
<code>PackageFile</code> rows on an internal version. Instead, <code>services/packages/cargo/index.go</code>
maintains the index as commits in a dedicated <strong>Gitea repository</strong> named <code>_cargo-index</code> inside
the owning user/organization, reusing <code>services/repository/files</code> (the same code path that
backs the web-based file-edit API) to create/update files:</p>
<pre class="highlight"><code class="language-go">const IndexRepositoryName = "_cargo-index"

func BuildPackagePath(name string) string {
    switch len(name) {
    case 1: return path.Join("1", name)
    case 2: return path.Join("2", name)
    case 3: return path.Join("3", string(name[0]), name)
    default: return path.Join(name[0:2], name[2:4], name)
    }
}

func RebuildIndex(ctx context.Context, doer, owner *user_model.User) error { /* rewrites every package's index file */ }
func UpdatePackageIndexIfExists(ctx context.Context, doer, owner *user_model.User, packageID int64) error { /* incremental */ }
func BuildPackageIndex(ctx context.Context, p *packages_model.Package) (*bytes.Buffer, error) { /* one crate's newline-delimited JSON entries */ }</code></pre>
<p><code>BuildPackagePath</code> implements Cargo's documented sharding scheme for the sparse index (1- and
2-character names get their own top-level bucket; 3+ character names are sharded by their
first four characters) so index file counts per directory stay bounded, mirroring the same
motivation as <a href="shared-infrastructure.html#sharded-key-layout"><code>KeyToRelativePath</code></a> for blob
storage — just applied to a Git tree instead of object storage. Each crate's index entry is one
line of JSON per published version (<code>IndexVersionEntry</code>), appended/rewritten by
<code>BuildPackageIndex</code>. <code>InitializeIndexRepository</code> provisions the <code>_cargo-index</code> repository (and
its <code>config.json</code>, served by <code>BuildConfig</code>, which tells <code>cargo</code> clients the <code>dl</code> download
endpoint and whether the registry requires auth) the first time an owner publishes a crate.</p>
<h2 id="manifest-graph-adapter-container-oci">Manifest-Graph Adapter: Container (OCI)<a href="#manifest-graph-adapter-container-oci" class="heading-anchor" aria-label="Link">#</a></h2>
<p>The container registry is architecturally the most complex adapter because the Docker
Registry HTTP API v2 / OCI Distribution Spec models a package as a <strong>graph</strong> of content-addressed
blobs (layers + config) referenced by a <strong>manifest</strong>, with support for chunked/resumable blob
uploads — a shape the other four <code>PackageFile</code>-per-artifact ecosystems don't need.</p>
<h3 id="chunked-blob-upload-servicespackagescontainerblob_uploadergo">Chunked blob upload (<code>services/packages/container/blob_uploader.go</code>)<a href="#chunked-blob-upload-servicespackagescontainerblob_uploadergo" class="heading-anchor" aria-label="Link">#</a></h3>
<p>OCI clients (<code>docker push</code>, <code>podman push</code>) push large layers across multiple <code>PATCH</code> requests
rather than one big <code>PUT</code>. <code>BlobUploader</code> bridges this streaming upload to Gitea's blob model:</p>
<pre class="highlight"><code class="language-go">// BlobUploader handles chunked blob uploads
type BlobUploader struct {
    *packages_model.PackageBlobUpload
    *packages_module.MultiHasher
    file    *os.File
    reading bool
}

func NewBlobUploader(ctx context.Context, id string) (*BlobUploader, error) {
    model, err := packages_model.GetBlobUploadByID(ctx, id)
    hash := packages_module.NewMultiHasher()
    if len(model.HashStateBytes) != 0 {
        hash.UnmarshalBinary(model.HashStateBytes) // resume hashing from a previous PATCH
    }
    // opens (or creates) a temp file under AppDataTempDir("package-upload") keyed by upload id
}</code></pre>
<p>Each <code>PATCH /v2/&lt;name&gt;/blobs/uploads/&lt;uuid&gt;</code> request:</p>
<ol>
<li>Loads the in-progress <code>PackageBlobUpload</code> row (see
   <a href="database-schema.html#supporting-tables">Database Schema — supporting tables</a>) and its
   serialized <code>MultiHasher</code> state.</li>
<li>Appends the new chunk to a temp file on disk <strong>and</strong> feeds it through the resumed hasher —
   so the whole blob is never buffered in memory and never re-hashed from the start.</li>
<li>Persists the updated <code>BytesReceived</code> and <code>HashStateBytes</code> back onto the row so the <em>next</em>
   <code>PATCH</code> (which may hit a different Gitea process behind a load balancer, since state lives
   in the DB/temp-dir rather than in-memory) can resume correctly.</li>
<li>On the final request (<code>PUT</code> with no body, or a <code>PATCH</code> immediately followed by finalize),
   the accumulated file and its now-complete <code>MultiHasher</code> sums are handed to the same
   <code>packages_service.NewPackageBlob</code> / <code>GetOrInsertBlob</code> path used by every other ecosystem,
   so container blobs still fully participate in cross-ecosystem content-addressable
   deduplication (<a href="shared-infrastructure.html">Shared Infrastructure</a>).</li>
</ol>
<p><code>errWriteAfterRead</code> and <code>errOffsetMismatch</code> guard against protocol violations (a client trying
to write after the uploader has already started being read back, or resuming at the wrong byte
offset relative to what the model believes has been received).</p>
<h3 id="manifest-parsing-servicespackagescontainercommongo">Manifest parsing (<code>services/packages/container/common.go</code>)<a href="#manifest-parsing-servicespackagescontainercommongo" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>ParseManifestMetadata</code> is called when a client <code>PUT</code>s a manifest (<code>PUT
/v2/&lt;name&gt;/manifests/&lt;reference&gt;</code>). It decodes the OCI/Docker manifest JSON, looks up the
<strong>config blob</strong> the manifest references by digest (via <code>models/packages/container</code>'s
<code>GetContainerBlob</code>, one of the ecosystem-specific model extensions described in
<a href="database-schema.html#ecosystem-specific-model-packages">Database Schema</a>), opens that blob from
the <code>ContentStore</code>, and hands it to <code>modules/packages/container.ParseImageConfig</code> to extract
image metadata (platform, created-by history, labels) that gets stored as the version's
<code>MetadataJSON</code>:</p>
<pre class="highlight"><code class="language-go">func ParseManifestMetadata(ctx context.Context, rd io.Reader, ownerID int64, imageName string) (*v1.Manifest, *packages_model.PackageFileDescriptor, *container_module.Metadata, error) {
    var manifest v1.Manifest
    json.NewDecoder(rd).Decode(&amp;manifest)
    configDescriptor, _ := container_service.GetContainerBlob(ctx, &amp;container_service.BlobSearchOptions{
        OwnerID: ownerID, Image: imageName, Digest: manifest.Config.Digest.String(),
    })
    configReader, _ := packages.NewContentStore().OpenBlob(packages.BlobHash256Key(configDescriptor.Blob.HashSHA256))
    return &amp;manifest, configDescriptor, container_module.ParseImageConfig(manifest.Config.MediaType, configReader), nil
}</code></pre>
<p>This is also where the OCI adapter diverges from the generic upload flow documented in
<a href="package-flow.html">Package Upload/Download Flow</a>: a manifest doesn't carry its own content
directly — it's a pointer to blobs that were already uploaded in prior requests — so
<code>services/packages/container</code> must resolve those references before it can build a
<code>PackageFileCreationInfo</code> and hand off to the shared <code>AddFileToPackageVersionInternal</code>/
<code>CreatePackageAndAddFile</code> helpers.</p>
<h3 id="auth-bearer-token-exchange-routersapipackagesauthgo">Auth: Bearer token exchange (<code>routers/api/packages/auth.go</code>)<a href="#auth-bearer-token-exchange-routersapipackagesauthgo" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Container (and Conan) clients authenticate via a Docker-Registry-style token exchange rather
than sending Basic/OAuth2 credentials on every request. <code>packages.Auth{}</code> (registered in
<code>CommonRoutes()</code>/<code>ContainerRoutes()</code>'s <code>verifyAuth</code> list alongside <code>OAuth2{}</code>, <code>Basic{}</code>,
<code>nuget.Auth{}</code>, and <code>chef.Auth{}</code>) verifies the short-lived Bearer token minted by
<code>services/packages/auth.go</code>'s <code>CreateAuthorizationToken</code>/<code>ParseAuthorizationToken</code>, resolving
it back to a <code>*user_model.User</code> — including special-cased <strong>ghost user</strong> (anonymous/public
pull, gated by <code>Auth.AllowGhostUser</code>) and <strong>Actions user</strong> (CI-triggered pushes) identities
that don't correspond to a real login. See <a href="supported-ecosystems.html#authentication">Supported Ecosystems —
Authentication</a> for how this fits alongside the other
ecosystems' auth quirks, and <a href="../07-rest-api/packages-and-actions-api.html">Packages &amp; Actions API</a>
for the full route mounting/middleware chain (<code>verifyAuth</code>, <code>reqPackageAccess</code>) shared by every
ecosystem including Container.</p>
<h3 id="cleanup-servicespackagescontainercleanupgo">Cleanup (<code>services/packages/container/cleanup.go</code>)<a href="#cleanup-servicespackagescontainercleanupgo" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Because manifests reference blobs rather than owning them exclusively, container image cleanup
(<code>Cleanup</code>, <code>ShouldBeSkipped</code>) must additionally guard against deleting a manifest whose blobs
are still referenced by another (e.g. shared base-image layers across tags), on top of the
generic <a href="package-flow.html#deletion-flow">deferred-delete blob cleanup</a> every ecosystem shares.</p>

      var mh=[];for(var m=0;m<h.h.length;m++){if(h.h[m].toLowerCase().indexOf(q)>=0)mh.push(h.h[m]);}
      for(var n=0;n<Math.min(mh.length,2);n++){html+='<div class="search-heading">↳ '+mh[n]+'</div>';}
    }
    if(!hits.length)html='<div style="padding:8px 12px;color:var(--text-dim);font-size:0.8rem">No results</div>';
    searchResults.innerHTML=html;
  });

(function(){
  // Mermaid expand buttons — added AFTER mermaid renders (so button is on wrapper, not inside pre)
  var overlay=document.getElementById('mermaid-overlay');
  var overlayInner=document.getElementById('mermaid-overlay-inner');
  function _addMermaidButtons(){
    document.querySelectorAll('.mermaid,pre.mermaid').forEach(function(el){
      if(el.dataset.expandAdded)return;
      el.dataset.expandAdded='1';
      // Wrap in a div so the button is a sibling of pre, not inside it
      var wrapper=document.createElement('div');
      wrapper.style.cssText='position:relative;display:inline-block;width:100%;';
      el.parentNode.insertBefore(wrapper,el);
      wrapper.appendChild(el);
      var btn=document.createElement('button');
      btn.className='mermaid-expand';btn.textContent='⛶';btn.title='Expand diagram';
      btn.addEventListener('click',function(e){
        e.stopPropagation();
        var clone=el.cloneNode(true);
        delete clone.dataset.expandAdded;
        clone.removeAttribute('data-expand-added');
        clone.style.cssText='background:none;border:none;padding:0;margin:0;text-align:center;min-width:70vw;max-width:90vw;';
        // Clear overlay content safely, keep close button
        overlayInner.innerHTML='';
        var closeBtn=document.createElement('button');
        closeBtn.className='mermaid-overlay-close';closeBtn.textContent='×';closeBtn.title='Close';
        closeBtn.addEventListener('click',function(){overlay.classList.remove('open');});
        overlayInner.appendChild(clone);
        overlayInner.appendChild(closeBtn);
        overlay.classList.add('open');
        // Re-run mermaid on the clone after it's in the DOM
        setTimeout(function(){
          if(window.mermaid){
            try{mermaid.run({nodes:[clone]});}catch(err){}
          }
        },50);
      });
      wrapper.appendChild(btn);
    });
  }
  // Wait for mermaid to finish rendering before adding buttons (mermaid init runs above)
  setTimeout(_addMermaidButtons,800);
  if(overlay){
    overlay.addEventListener('click',function(e){if(e.target===overlay)overlay.classList.remove('open');});
    document.addEventListener('keydown',function(e){if(e.key==='Escape')overlay.classList.remove('open');});
  }
  // Code copy buttons
  document.querySelectorAll('pre').forEach(function(pre){
    if(pre.classList.contains('mermaid'))return;
    var btn=document.createElement('button');
    btn.className='code-copy';btn.textContent='Copy';
    btn.addEventListener('click',function(){
      var code=pre.querySelector('code');
      var text=code?code.textContent:pre.textContent;
      navigator.clipboard.writeText(text).then(function(){btn.textContent='Copied!';setTimeout(function(){btn.textContent='Copy';},2000);});
    });
    pre.appendChild(btn);
  });
  // Back to top
  var btt=document.getElementById('back-to-top');
  if(btt){
    window.addEventListener('scroll',function(){btt.style.display=window.scrollY>300?'flex':'none';});
    btt.addEventListener('click',function(){window.scrollTo({top:0,behavior:'smooth'});});
  }
  // TOC active scroll tracking
  var tocLinks=document.querySelectorAll('.toc-aside a[data-anchor]');
  if(tocLinks.length>0){
    var headingEls=[];
    tocLinks.forEach(function(l){var el=document.getElementById(l.dataset.anchor);if(el)headingEls.push({el:el,link:l});});
    var tocAside=document.querySelector('.toc-aside');
    var onScroll=function(){
      var scrollPos=window.scrollY+80;
      var active=null;
      for(var i=0;i<headingEls.length;i++){if(headingEls[i].el.offsetTop<=scrollPos)active=headingEls[i];}
      tocLinks.forEach(function(l){l.classList.remove('toc-active');});
      if(active){
        active.link.classList.add('toc-active');
        // Scroll active link into view within the TOC panel, not the page
        if(tocAside){
          var linkTop=active.link.offsetTop-tocAside.offsetTop;
          var visibleTop=tocAside.scrollTop;
          var visibleBottom=visibleTop+tocAside.clientHeight;
          if(linkTop<visibleTop+40||linkTop>visibleBottom-40){
            tocAside.scrollTop=linkTop-tocAside.clientHeight/2;
          }
        }
      }
    };
    window.addEventListener('scroll',onScroll);
    onScroll();
    // Prevent TOC links from scrolling the TOC panel to top on click
    tocLinks.forEach(function(l){
      l.addEventListener('click',function(e){
        e.preventDefault();
        var anchor=l.dataset.anchor;
        var target=document.getElementById(anchor);
        if(target){target.scrollIntoView({behavior:'smooth',block:'start'});}
      });
    });
  }
  // Persist sidebar scroll position across page navigations
  var sidebarEl=document.querySelector('nav.sidebar');
  if(sidebarEl){
    var sidebarKey='sasva-sidebar-scroll';
    // Restore scroll position on page load
    var savedScroll=sessionStorage.getItem(sidebarKey);
    if(savedScroll){sidebarEl.scrollTop=parseInt(savedScroll,10);}
    // Save scroll position before navigating away
    document.querySelectorAll('#sidebar-nav-links a').forEach(function(a){
      a.addEventListener('click',function(){
        sessionStorage.setItem(sidebarKey,String(sidebarEl.scrollTop));
      });
    });
    // Also scroll active item into view on load
    var activeLink=sidebarEl.querySelector('a.active');
    if(activeLink&&!savedScroll){
      var linkOffset=activeLink.offsetTop-sidebarEl.offsetTop;
      sidebarEl.scrollTop=Math.max(0,linkOffset-sidebarEl.clientHeight/2);
    }
  }
})();
