<h1>Issue Tracking Workflow</h1>
<h1 id="issue-tracking-workflow">Issue Tracking Workflow</h1>
<p>This page walks through the end-to-end life of an <code>Issue</code> — creation, labelling, milestones,
assignees, cross-references, and time tracking — as implemented by <code>services/issue</code> on top of the
<code>models/issues</code> tables described in
<a href="../05-database-models/issues-and-pulls-model.html">Issues &amp; Pull Requests Model</a>. It complements
that model reference by focusing on the <em>service-layer orchestration</em>: what happens, in what order,
and which notifications fire, each time an issue changes.</p>
<p>Source: <code>services/issue/*.go</code>, <code>modules/label/*.go</code>, <code>modules/references/references.go</code>,
<code>models/issues/{issue,issue_label,milestone,tracked_time,stopwatch,issue_xref}.go</code>.</p>
<h2 id="creating-an-issue-newissue">Creating an Issue — <code>NewIssue</code><a href="#creating-an-issue-newissue" class="heading-anchor" aria-label="Link">#</a></h2>
<pre class="highlight"><code class="language-go">func NewIssue(ctx context.Context, repo *repo_model.Repository, issue *issues_model.Issue,
    labelIDs []int64, uuids []string, assigneeIDs, projectIDs []int64) error</code></pre>
<p>(<code>services/issue/issue.go</code>)</p>
<ol>
<li>Loads the poster and rejects the call with <code>user_model.ErrBlockedUser</code> if the poster is blocked
   by the repo owner or by any of the requested assignees (Gitea's user-blocking feature applies at
   creation time, not just afterwards).</li>
<li>Inside a single DB transaction:</li>
<li><code>issues_model.NewIssue(ctx, repo, issue, labelIDs, uuids)</code> inserts the <code>Issue</code> row (allocating
     its per-repo <code>Index</code> via the shared <code>ResourceIndex</code> counter — see the model page), attaches the
     given labels, and links the given attachment UUIDs.</li>
<li>For each <code>assigneeID</code>, loads the user and calls <code>AddAssigneeIfNotAssigned</code>, collecting the
     <code>Comment</code> each assignment produces (used later for per-assignee notifications).</li>
<li>If <code>projectIDs</code> is non-empty, <code>IssueAssignOrRemoveProject</code> places the issue onto the given
     project board(s)/column(s).</li>
<li>Outside the transaction (so notification failures never roll back the issue itself):</li>
<li><code>FindAndUpdateIssueMentions</code> scans the issue body for <code>@user</code> mentions and records them.</li>
<li><code>notify_service.NewIssue</code> fires the "new issue" notification (in-app + webhook + mail).</li>
<li>If labels were attached, <code>notify_service.IssueChangeLabels</code>.</li>
<li>If a milestone was set at creation, <code>notify_service.IssueChangeMilestone</code>.</li>
<li>One <code>notify_service.IssueChangeAssignee</code> call per assignee, carrying that assignee's specific
     comment from step 2.</li>
</ol>
<h2 id="labels-moduleslabel-servicesissuelabelgo">Labels — <code>modules/label</code> + <code>services/issue/label.go</code><a href="#labels-moduleslabel-servicesissuelabelgo" class="heading-anchor" aria-label="Link">#</a></h2>
<h3 id="label-templates">Label templates<a href="#label-templates" class="heading-anchor" aria-label="Link">#</a></h3>
<p>New repositories/organizations can seed their label set from a <strong>template</strong> file
(<code>modules/label/parser.go</code>, loaded via <code>options.Labels</code>). Two formats are supported:</p>
<ul>
<li><strong>YAML</strong> (<code>.yaml</code>/<code>.yml</code>) — a <code>labels:</code> list of <code>{name, color, description, exclusive,
  exclusive_order}</code> objects (<code>modules/label/label.go</code> <code>Label</code> struct).</li>
<li><strong>Legacy line format</strong> — <code>&lt;color&gt; &lt;name&gt;; &lt;description&gt;</code> per line, parsed by
  <code>parseLegacyFormat</code>.</li>
</ul>
<p>Every color, in either format, is normalized by <code>NormalizeColor</code>: it trims/lowercases the string,
accepts 3- or 6-hex-digit forms with or without a leading <code>#</code>, expands the 3-digit shorthand, and
validates against <code>^#([0-9a-f]{3}|[0-9a-f]{6})$</code> — an invalid color aborts template loading with
<code>ErrTemplateLoad</code>.</p>

<h2 id="milestones-servicesissuemilestonego">Milestones — <code>services/issue/milestone.go</code><a href="#milestones-servicesissuemilestonego" class="heading-anchor" aria-label="Link">#</a></h2>

<li>If assigning to a new milestone (<code>issue.MilestoneID &gt; 0</code>), verifies that milestone actually

<ul>

  <code>issues_model.ToggleIssueAssignee</code>, which also creates the <code>CommentTypeAssignees</code> comment,

<li><strong><code>ToggleAssigneeWithNotify</code></strong> wraps the above and additionally fires

<li><strong><code>DeleteNotPassedAssignee(ctx, issue, doer, assignees)</code></strong> implements "replace the whole assignee

<p><code>findActionKeywords</code> (further down the same file) recognizes the configured <strong>close/reopen

tags it with an <code>XRefAction</code>:</p>
<pre class="highlight"><code class="language-go">type XRefAction int64

    XRefActionNone     XRefAction = iota // plain mention, no side effect
    XRefActionCloses                     // closes the referenced issue when resolved

<p><code>Issue.AddCrossReferences(ctx, doer, removeOld)</code> (<code>models/issues/issue_xref.go</code>) is called whenever
an issue/PR's title or body changes (creation, edit, or a new comment): it re-scans the content,
resolves each raw reference to a real <code>Issue</code> row, and creates/updates <code>Comment</code> rows of type
<code>CommentTypeIssueRef</code>/<code>CommentTypePullRef</code> with <code>RefIssueID</code>, <code>RefCommentID</code>, and <code>RefAction</code> set on
the <em>referenced</em> issue — this is what makes "mentioned in #456" show up on an issue's timeline.
When <code>removeOld</code> is set, <code>findOldCrossReferences</code> finds previously-recorded references from the
same issue/comment that no longer appear in the updated content and neuters them
(<code>neuterCrossReferencesIDs</code>, flips <code>RefAction</code> to <code>XRefActionNeutered</code>) rather than deleting them,
preserving the timeline history while dropping their close/reopen effect.</p>
<h2 id="time-tracking-modelsissuestracked_timestopwatchgo">Time Tracking — <code>models/issues/{tracked_time,stopwatch}.go</code><a href="#time-tracking-modelsissuestracked_timestopwatchgo" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Two related tables back the "start/stop timer, or add time manually" feature:</p>
<ul>
<li><strong><code>Stopwatch</code></strong> — at most one active row per <code>(IssueID, UserID)</code>, representing a running timer
  started via the <code>CommentTypeStartTracking</code> action. Stopping it (<code>CommentTypeStopTracking</code>)
  computes the elapsed duration and inserts a <code>TrackedTime</code> row for it.</li>
<li><strong><code>TrackedTime</code></strong> (<code>models/issues/tracked_time.go</code>) — one row per logged time entry:
  <code>{IssueID, UserID, Time (seconds), Deleted}</code>. <code>LoadAttributes</code> lazily loads the <code>Issue</code> (and its
  <code>Repo</code>) and the <code>User</code> (falling back to a ghost user if the original user was deleted).
  <code>Issue.LoadTotalTimes(ctx)</code> sums non-deleted <code>TrackedTime.Time</code> for the issue to show the total
  logged time on the issue page.</li>
</ul>
<p>Manual entries (as opposed to timer-derived ones) go through <code>CommentTypeAddTimeManual</code>, and
deleting a logged entry produces <code>CommentTypeDeleteTimeManual</code> — both recorded as issue-timeline
comments so the history of who logged what time is auditable. The <code>@2h30m</code> inline shorthand
recognized by <code>timeLogPattern</code> above lets a commenter log time directly from a comment body instead
of using the timer UI.</p>
<h2 id="closing-reopening">Closing / Reopening<a href="#closing-reopening" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Closing or reopening an issue (<code>issues_model.SetIssueAsClosed</code>, invoked directly by users, or
indirectly by a merge via <code>SetMerged</code>, or by a resolved <code>Closes #N</code> cross-reference) flips
<code>IsClosed</code> and <code>ClosedUnix</code>, decrements/increments the repo's open/closed issue counters and the
containing milestone's counters, and records a <code>CommentTypeClose</code>/<code>CommentTypeReopen</code> comment.
<code>Issue.IsOverdue()</code> compares <code>DeadlineUnix</code> against <code>ClosedUnix</code> (if closed) or the current time —
an issue closed before its deadline is never considered overdue, even later, since the comparison
uses the closing timestamp rather than "now."</p>
<h2 id="deleting-an-issue-deleteissue">Deleting an Issue — <code>DeleteIssue</code><a href="#deleting-an-issue-deleteissue" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>DeleteIssue(ctx, doer, issue)</code> (<code>services/issue/issue.go</code>) is the exhaustive teardown path:</p>
<ol>
<li>Loads full attributes and the <code>PullRequest</code> extension (if any).</li>
<li><code>deleteIssue</code> removes the <code>Issue</code> row and, in the same transaction, every satellite row that
   references it: <code>ContentHistory</code>, <code>Comment</code> (both <code>IssueID=</code> and, separately,
   <code>RefIssueID=</code>/<code>DependentIssueID=</code> — i.e. comments <em>about</em> this issue on other issues too),
   <code>IssueLabel</code>, <code>IssueDependency</code> (both directions), <code>IssueAssignees</code>, <code>IssueUser</code>,
   <code>activities_model.Notification</code>, <code>Reaction</code>, <code>IssueWatch</code>, <code>Stopwatch</code>, <code>TrackedTime</code>,
   <code>ProjectIssue</code>, <code>Attachment</code>, <code>PullRequest</code>, and <code>IssuePin</code> — then decrements the repo's
   issue/PR counters and the milestone's counters.</li>
<li>If the issue was a pull request, its <code>refs/pull/&lt;n&gt;/head</code> ref is removed from the base repo
   (<code>gitrepo.RemoveRef</code>) so the git side is cleaned up too.</li>
<li>Attachment files are removed from storage only <em>after</em> the transaction commits
   (<code>system_model.RemoveStorageWithNotice</code>), so a failed transaction never orphans deletes files
   that are still referenced by rows that got rolled back.</li>
<li><code>notify_service.DeleteIssue</code> fires last.</li>
</ol>
<p><code>DeleteIssuesByRepoID</code> and <code>DeleteOrphanedIssues</code> reuse the same <code>deleteIssue</code> primitive to clean up
every issue in a deleted repository, or issues whose owning repository row is already gone,
respectively — both process issues page-by-page (<code>db.DefaultMaxInSize</code> at a time) to bound memory
use on large repositories.</p>

      navigator.clipboard.writeText(text).then(function(){btn.textContent='Copied!';setTimeout(function(){btn.textContent='Copy';},2000);});
    });
    pre.appendChild(btn);
  });
  // Back to top
  var btt=document.getElementById('back-to-top');
  if(btt){
    window.addEventListener('scroll',function(){btt.style.display=window.scrollY>300?'flex':'none';});
    btt.addEventListener('click',function(){window.scrollTo({top:0,behavior:'smooth'});});
  }
  // TOC active scroll tracking
  var tocLinks=document.querySelectorAll('.toc-aside a[data-anchor]');
  if(tocLinks.length>0){
    var headingEls=[];
    tocLinks.forEach(function(l){var el=document.getElementById(l.dataset.anchor);if(el)headingEls.push({el:el,link:l});});
    var tocAside=document.querySelector('.toc-aside');
    var onScroll=function(){
      var scrollPos=window.scrollY+80;
      var active=null;
      for(var i=0;i<headingEls.length;i++){if(headingEls[i].el.offsetTop<=scrollPos)active=headingEls[i];}
      tocLinks.forEach(function(l){l.classList.remove('toc-active');});
      if(active){
        active.link.classList.add('toc-active');
        // Scroll active link into view within the TOC panel, not the page
        if(tocAside){
          var linkTop=active.link.offsetTop-tocAside.offsetTop;
          var visibleTop=tocAside.scrollTop;
          var visibleBottom=visibleTop+tocAside.clientHeight;
          if(linkTop<visibleTop+40||linkTop>visibleBottom-40){
            tocAside.scrollTop=linkTop-tocAside.clientHeight/2;
          }
        }
      }
    };
    window.addEventListener('scroll',onScroll);
    onScroll();
    // Prevent TOC links from scrolling the TOC panel to top on click
    tocLinks.forEach(function(l){
      l.addEventListener('click',function(e){
        e.preventDefault();
        var anchor=l.dataset.anchor;
        var target=document.getElementById(anchor);
        if(target){target.scrollIntoView({behavior:'smooth',block:'start'});}
      });
    });
  }
  // Persist sidebar scroll position across page navigations
  var sidebarEl=document.querySelector('nav.sidebar');
  if(sidebarEl){
    var sidebarKey='sasva-sidebar-scroll';
    // Restore scroll position on page load
    var savedScroll=sessionStorage.getItem(sidebarKey);
    if(savedScroll){sidebarEl.scrollTop=parseInt(savedScroll,10);}
    // Save scroll position before navigating away
    document.querySelectorAll('#sidebar-nav-links a').forEach(function(a){
      a.addEventListener('click',function(){
        sessionStorage.setItem(sidebarKey,String(sidebarEl.scrollTop));
      });
    });
    // Also scroll active item into view on load
    var activeLink=sidebarEl.querySelector('a.active');
    if(activeLink&&!savedScroll){
      var linkOffset=activeLink.offsetTop-sidebarEl.offsetTop;
      sidebarEl.scrollTop=Math.max(0,linkOffset-sidebarEl.clientHeight/2);
    }
  }
})();
