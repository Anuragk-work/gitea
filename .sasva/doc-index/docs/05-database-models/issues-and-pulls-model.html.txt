<h1>Issues & Pull Requests Model</h1>
<h1 id="issues-pull-requests-model">Issues &amp; Pull Requests Model</h1>
<p>Issues and pull requests share a single underlying table in Gitea — a pull request <strong>is</strong> an
<code>Issue</code> row with <code>IsPull = true</code>, extended by a linked <code>PullRequest</code> row. This page covers the
<code>Issue</code> entity, its many satellite tables (comments, labels, milestones, reactions,
dependencies, time tracking), the <code>PullRequest</code> extension, and the code-review model.</p>
<p>Source: <code>models/issues/</code> (package <code>issues</code>).</p>
<h2 id="the-issue-struct">The <code>Issue</code> Struct<a href="#the-issue-struct" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>models/issues/issue.go</code>:</p>
<pre class="highlight"><code class="language-go">type Issue struct {
    ID                int64                  `xorm:"pk autoincr"`
    RepoID            int64                  `xorm:"INDEX UNIQUE(repo_index)"`
    Repo              *repo_model.Repository `xorm:"-"`
    Index             int64                  `xorm:"UNIQUE(repo_index)"` // per-repo issue number
    PosterID          int64                  `xorm:"INDEX"`
    Poster            *user_model.User       `xorm:"-"`
    Title             string                 `xorm:"name"`
    Content           string                 `xorm:"LONGTEXT"`
    RenderedContent   template.HTML          `xorm:"-"`
    ContentVersion    int                    `xorm:"NOT NULL DEFAULT 0"` // optimistic-lock counter
    Labels            []*Label               `xorm:"-"`
    MilestoneID       int64                  `xorm:"INDEX"`
    Milestone         *Milestone             `xorm:"-"`
    Projects          []*project_model.Project `xorm:"-"`
    Priority          int
    AssigneeID        int64            `xorm:"-"`
    Assignee          *user_model.User `xorm:"-"`
    IsClosed          bool             `xorm:"INDEX"`
    IsPull            bool             `xorm:"INDEX"` // true =&gt; this row is a pull request
    PullRequest       *PullRequest     `xorm:"-"`
    NumComments       int
    Ref               string // TODO: RemoveIssueRef

    PinOrder     int                `xorm:"-"` // 0=not loaded, -1=loaded-not-pinned
    DeadlineUnix timeutil.TimeStamp `xorm:"INDEX"`
    CreatedUnix, UpdatedUnix, ClosedUnix timeutil.TimeStamp

    Attachments      []*repo_model.Attachment `xorm:"-"`
    Comments         CommentList              `xorm:"-"`
    Reactions        ReactionList             `xorm:"-"`
    TotalTrackedTime int64                    `xorm:"-"`
    Assignees        []*user_model.User       `xorm:"-"`

    IsLocked bool `xorm:"NOT NULL DEFAULT false"` // limits commenting to write-access users

    ShowRole     RoleDescriptor `xorm:"-"` // "role" badge shown in UI (owner/member/contributor…)
    TimeEstimate int64          `xorm:"NOT NULL DEFAULT 0"`
}</code></pre>
<p>Key points:</p>
<ul>
<li><code>(RepoID, Index)</code> is unique — <code>Index</code> is the human-visible issue/PR number (<code>#123</code>),
  allocated per-repository via <code>IssueIndex</code> (<code>models/issues/issue_index.go</code>), which wraps
  <code>db.ResourceIndex</code> (a per-resource atomic counter table shared with other numbered entities).</li>
<li><code>IsPull</code> is the discriminator between "plain issue" and "pull request" — both live in the same
  <code>issue</code> table and share comments, labels, milestones, reactions, assignees, and time tracking.</li>
<li>Most relations (<code>Repo</code>, <code>Poster</code>, <code>Labels</code>, <code>Milestone</code>, <code>Assignee</code>, <code>Comments</code>, …) are
  <code>xorm:"-"</code> — not columns — and populated by explicit <code>Load*</code> methods
  (<code>LoadRepo</code>, <code>LoadPoster</code>, <code>LoadLabels</code>, <code>LoadMilestone</code>, <code>LoadAttachments</code>, …), each guarded by
  an <code>isXLoaded</code> flag to avoid redundant queries.</li>
<li><code>LoadTotalTimes(ctx)</code> sums <code>TrackedTime.Time</code> for the issue (see Time Tracking below).</li>
<li><code>IsOverdue()</code> compares <code>DeadlineUnix</code> against <code>ClosedUnix</code> (if closed) or "now".</li>
</ul>

<h2 id="time-tracking-stopwatch-trackedtime">Time Tracking — Stopwatch &amp; TrackedTime<a href="#time-tracking-stopwatch-trackedtime" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Two cooperating tables, both gated by <code>IssuesConfig.EnableTimetracker</code> /
<code>AllowOnlyContributorsToTrackTime</code>:</p>
<pre class="highlight"><code class="language-go">// models/issues/stopwatch.go — an active, running timer

    IssueID     int64 `xorm:"INDEX"`
    UserID      int64 `xorm:"INDEX"`

}

// models/issues/tracked_time.go — a finalized, recorded time entry

    ID          int64
    IssueID     int64  `xorm:"INDEX"`
    Issue       *Issue `xorm:"-"`
    UserID      int64  `xorm:"INDEX"`
    User        *user_model.User `xorm:"-"`
    Created     time.Time `xorm:"-"`
    CreatedUnix int64     `xorm:"created"`
    Time        int64     `xorm:"NOT NULL"` // seconds
    Deleted     bool      `xorm:"NOT NULL DEFAULT false"`
}</code></pre>
<p>Flow: a user starts a <code>Stopwatch</code> on an issue (one active stopwatch per user+issue, enforced by
<code>getStopwatch</code>). Stopping the stopwatch (or the "add time manually" action) inserts a
<code>TrackedTime</code> row and deletes the <code>Stopwatch</code> row. <code>TrackedTime</code> rows are soft-deleted
(<code>Deleted = true</code>) rather than removed, so historical time reports remain auditable.
<code>Issue.LoadTotalTimes</code> sums non-deleted <code>TrackedTime.Time</code> for the issue.</p>

<h2 id="code-review-modelsissuesreviewgo">Code Review — <code>models/issues/review.go</code><a href="#code-review-modelsissuesreviewgo" class="heading-anchor" aria-label="Link">#</a></h2>

<ul>

  the reviewer's general feedback text.</li>
<li><code>ReviewTypeRequest</code> reviews are synthetic placeholder rows created when a reviewer/team is
  requested, so the "requested reviewers" list can be queried the same way as submitted reviews.</li>
</ul>
