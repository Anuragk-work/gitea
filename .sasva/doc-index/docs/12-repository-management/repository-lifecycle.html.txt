<h1>Repository Lifecycle</h1>
<h1 id="repository-lifecycle">Repository Lifecycle</h1>
<p>This page walks through every way a <code>Repository</code> row comes into existence, how it transitions
between states, and how it eventually stops existing — backed by <code>services/repository</code> (create,
fork, adopt, migrate, transfer, archive/unarchive, delete) and <code>services/migrations</code>
(third-party import orchestration). For the entity's columns and satellite tables (mirrors,
releases, forks, wiki, units), see <a href="../05-database-models/repository-model.html">Repository Model</a>.</p>
<h2 id="overview-of-entry-points">Overview of Entry Points<a href="#overview-of-entry-points" class="heading-anchor" aria-label="Link">#</a></h2>
<table>
<thead>
<tr>
<th>Entry point</th>
<th>Service function</th>
<th>Typical caller</th>
</tr>
</thead>
<tbody>
<tr>
<td>Create new (empty or auto-initialized) repo</td>
<td><code>repository.CreateRepositoryDirectly</code> (<code>services/repository/create.go</code>)</td>
<td><code>POST /repos</code> API, "New Repository" web form</td>
</tr>
<tr>
<td>Fork an existing repo</td>
<td><code>repository.ForkRepository</code> (<code>services/repository/fork.go</code>)</td>
<td>"Fork" button, <code>POST /repos/{owner}/{repo}/forks</code></td>
</tr>
<tr>
<td>Adopt an existing on-disk bare repo not yet tracked in the DB</td>
<td><code>repository.AdoptRepository</code> (<code>services/repository/adopt.go</code>)</td>
<td>Admin "unadopted repositories" panel</td>
</tr>
<tr>
<td>Generate from a template repository</td>
<td><code>repository.GenerateRepository</code> (<code>services/repository/generate.go</code>)</td>
<td>"Use this template" button</td>
</tr>
<tr>
<td>Migrate/clone from an external Git host (optionally as a mirror)</td>
<td><code>repository.CreateRepositoryDirectly</code> (status <code>RepositoryBeingMigrated</code>) + <code>repository.MigrateRepositoryGitData</code> (<code>services/repository/migrate.go</code>), driven by <code>services/migrations</code></td>
<td>"Migrate/New Migration" web form, <code>POST /repos/migrate</code></td>
</tr>
<tr>
<td>Transfer ownership</td>
<td><code>repository.StartRepositoryTransfer</code> / <code>AcceptTransferOwnership</code> (<code>services/repository/transfer.go</code>)</td>
<td>Repo settings → "Transfer Ownership"</td>
</tr>
<tr>
<td>Archive / unarchive</td>
<td><code>repo_model.SetArchiveRepoState</code> via <code>routers/web/repo/setting</code> handlers</td>
<td>Repo settings → "Archive/Unarchive this repository"</td>
</tr>
<tr>
<td>Delete</td>
<td><code>repository.DeleteRepositoryDirectly</code> (<code>services/repository/delete.go</code>)</td>
<td>Repo settings → "Delete this repository", <code>DELETE /repos/{owner}/{repo}</code></td>
</tr>

<p>All of the "create-like" paths (<code>CreateRepositoryDirectly</code>, <code>ForkRepository</code>,
<code>AdoptRepository</code>, <code>GenerateRepository</code>, and the migration create step) funnel through a shared
private helper, <code>createRepositoryInDB</code> (in <code>services/repository/repository.go</code>), inside a
<code>db.WithTx</code> transaction. That helper:</p>
<ol>
<li>Verifies name legality/uniqueness (<code>repo_model.IsUsableRepoName</code>, checks for existing rows).</li>
<li>Inserts the <code>Repository</code> row and the default set of <code>RepoUnit</code>s (<code>unit.DefaultRepoUnits</code>,
   or <code>unit.DefaultForkRepoUnits</code> for forks).</li>
<li>Bumps <code>Owner.NumRepos</code>, grants org "include all repositories" teams and admin-collaborator
   access to <code>doer</code>, sets up default watch (if <code>setting.Service.AutoWatchNewRepos</code>), and copies
   any default webhooks (<code>webhook.CopyDefaultWebhooksToRepo</code>).</li>
</ol>
<p>If anything after the DB transaction fails (git init, clone, label init, etc.), a <code>defer</code>
guard calls <code>cleanupRepository</code>, which invokes <code>DeleteRepositoryDirectly</code> to fully undo the
partially-created repository — this is why creation failures never leave orphaned DB rows or
half-initialized git directories under normal operation.</p>
<h2 id="create-createrepositorydirectly">Create — <code>CreateRepositoryDirectly</code><a href="#create-createrepositorydirectly" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>services/repository/create.go</code>:</p>
<ol>
<li><strong>Authorization</strong> — <code>doer.CanCreateRepoIn(owner)</code> checks <code>owner.MaxRepoCreation</code> limits.</li>
<li><strong>Validation</strong> — issue-label template existence, object format (<code>sha1</code>/<code>sha256</code>).</li>
<li><strong>DB insert</strong> — <code>createRepositoryInDB</code> inside a transaction.</li>
<li><strong>Mirror short-circuit</strong> — if <code>opts.IsMirror</code>, the function returns immediately after the DB
   insert; the actual git clone happens later via <code>MigrateRepositoryGitData</code> (mirrors are always
   created through the migration path, never through plain "New Repository").</li>
<li><strong>On-disk init</strong> (<code>initRepository</code>) — <code>gitrepo.InitRepository</code> (bare git init) +
   <code>gitrepo.CreateDelegateHooks</code> (installs Gitea's server-side hooks), then if <code>AutoInit</code> is set:
   clones to a temp dir, renders README/<code>.gitignore</code>/<code>LICENSE</code> templates
   (<code>options.Readme</code>/<code>options.Gitignore</code>/<code>repo_module.GetLicense</code>, with <code>${Name}</code>,
   <code>${CloneURL.SSH}</code>, etc. expanded via <code>modules/templates/vars</code>), commits, and pushes back.
   Finally sets the default branch and calls <code>repo_module.SyncRepoBranches</code> +
   <code>repo_module.UpdateRepoSize</code>.</li>
<li><strong>Label initialization</strong> (<code>repo_module.InitializeLabels</code>) if an issue-label template was
   requested.</li>
<li><strong>Post-create git housekeeping</strong> (<code>updateGitRepoAfterCreate</code>) — <code>CheckDaemonExportOK</code> (writes
   <code>git-daemon-export-ok</code> based on repo visibility for the <code>git://</code> protocol) and
   <code>git update-server-info</code> (refreshes dumb-HTTP transport metadata).</li>
</ol>
<h2 id="fork-forkrepository">Fork — <code>ForkRepository</code><a href="#fork-forkrepository" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>services/repository/fork.go</code>:</p>
<ul>
<li>Blocks if the doer is blocked by the base repo's owner, or the owner has hit
  <code>MaxRepoCreation</code>, or a fork already exists for that owner (<code>ErrForkAlreadyExist</code>).</li>
<li>Creates the DB row with <code>IsFork: true</code>, <code>ForkID: &lt;base repo ID&gt;</code>,
  <code>Status: RepositoryBeingMigrated</code> (a fork is briefly "being migrated" while its git data is
  copied), and increments <code>NumForks</code> on the base repo (<code>IncrementRepoForkNum</code>) — all inside the
  same transaction as <code>createRepositoryInDB</code>, along with <code>git_model.CopyLFS</code> to copy LFS
  pointers.</li>
<li>Clones the base repository's git data (<code>gitrepo.Clone</code>, optionally <code>SingleBranch</code>), re-runs
  <code>updateGitRepoAfterCreate</code>, recreates hooks, and syncs branches/releases from the freshly
  cloned git data (<code>SyncRepoBranchesWithRepo</code>, <code>SyncReleasesWithTags</code>).</li>
<li>Copies language stats and license detection from the base repo, then flips
  <code>Status</code> back to <code>RepositoryReady</code> and fires <code>notify_service.ForkRepository</code>.</li>
<li><code>ConvertForkToNormalRepository</code> detaches a fork (clears <code>IsFork</code>/<code>ForkID</code>, decrements the base
  repo's <code>NumForks</code>) without touching git data — used when a base repo is deleted or an admin
  "un-forks" a repository.</li>
</ul>
<h2 id="migrate-and-mirror-on-migrate-migraterepositorygitdata">Migrate (and Mirror-on-Migrate) — <code>MigrateRepositoryGitData</code><a href="#migrate-and-mirror-on-migrate-migraterepositorygitdata" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>services/repository/migrate.go</code>, invoked by <code>services/migrations</code> after
<code>CreateRepositoryDirectly</code> has created the placeholder DB row with
<code>Status: RepositoryBeingMigrated</code>:</p>
<ol>
<li>Deletes any stale directory at the target path, then clones from the source with
   <code>--mirror</code> semantics (<code>git.CloneRepoOptions{Mirror: true}</code>) so all refs (branches, tags, and
   for mirrors, subsequent updates) are captured; <code>gitrepo.WriteCommitGraph</code> speeds up later log
   operations.</li>
<li>If <code>opts.Wiki</code>, clones the source's wiki (<code>&lt;url&gt;.wiki.git</code> convention, resolved by
   <code>repo_module.WikiRemoteURL</code>) the same way via <code>cloneWiki</code>.</li>
<li>Detects emptiness, resolves the default branch from the remote <code>HEAD</code>, and syncs
   branches/releases into the DB (<code>SyncRepoBranchesWithRepo</code>, <code>SyncReleasesWithTags</code> — skipped
   for releases if the caller requested a separate release-migration pass).</li>
<li>If <code>opts.LFS</code>, walks the repo for LFS pointers missing content and downloads them
   (<code>repo_module.StoreMissingLfsObjectsInRepository</code>) via an LFS client built from the source
   endpoint.</li>
<li><strong>Branch point — mirror vs. one-shot migration:</strong></li>
<li><strong>If <code>opts.Mirror</code>:</strong> inserts a <code>repo_model.Mirror</code> row (<code>Interval</code> from
     <code>setting.Mirror.DefaultInterval</code> or the caller-supplied <code>MirrorInterval</code>, <code>EnablePrune:
     true</code>, <code>LFS</code>/<code>LFSEndpoint</code> if applicable), computes <code>NextUpdateUnix</code>, sets
     <code>Repository.IsMirror = true</code>, and adds a <code>remote.&lt;name&gt;.fetch</code> refspec for tags so future
     <code>git remote update</code> calls keep tags in sync. The repository keeps its <code>origin</code> remote
     pointing at the source — this is what the pull-mirror sync cron later fetches from.</li>
<li><strong>Else (plain migration):</strong> calls <code>CleanUpMigrateInfo</code>, which installs hooks (for the repo
     and, if present, its wiki), removes the <code>origin</code> remote (a migrated repo is standalone —
     there is nothing to keep syncing), and calls <code>UpdateRepository</code> to persist final state.</li>
<li>Optionally enables the <code>Releases</code>/<code>Wiki</code> repo units if content for them was imported.</li>
<li>On success the caller (in <code>services/migrations</code>) flips <code>Status</code> to <code>RepositoryReady</code>; on
   failure, the placeholder repository is cleaned up the same way as any other failed creation.</li>
</ol>
<h2 id="adopt-an-existing-directory-adoptrepository">Adopt an Existing Directory — <code>AdoptRepository</code><a href="#adopt-an-existing-directory-adoptrepository" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>services/repository/adopt.go</code> handles the admin-only workflow for git directories that exist
on disk (e.g. restored from backup, or manually placed) but have no corresponding DB row:</p>
<ul>
<li><code>ListUnadoptedRepositories</code> scans owners' storage directories and diffs them against known
  DB repositories to build the "unadopted repositories" admin list.</li>
<li><code>AdoptRepository</code> creates the DB row exactly like <code>CreateRepositoryDirectly</code> would (via
  <code>createRepositoryInDB</code>), but skips git-init/clone — instead it verifies the directory really
  exists and is non-empty, installs hooks, detects/sets the default branch, and syncs
  branches/tags/releases from the pre-existing git data.</li>
<li><code>DeleteUnadoptedRepository</code> is the inverse admin action: removes an unadopted directory from
  disk without ever creating a DB row.</li>
</ul>
<h2 id="transfer-ownership-startrepositorytransfer-accepttransferownership">Transfer Ownership — <code>StartRepositoryTransfer</code> / <code>AcceptTransferOwnership</code><a href="#transfer-ownership-startrepositorytransfer-accepttransferownership" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>services/repository/transfer.go</code>:</p>
<ul>
<li><code>StartRepositoryTransfer</code> acquires a per-repo global lock (<code>globallock.Lock</code> on
  <code>repo_working_&lt;id&gt;</code>) and requires <code>repo.Status == RepositoryReady</code>
  (<code>TestRepositoryReadyForTransfer</code>).</li>
<li><strong>Direct transfer</strong> (no acceptance needed) happens when the doer is a site admin, transfers a
  repo back to themselves, or the destination is an org the doer can already create repos in
  (<code>organization.CanCreateOrgRepo</code>) — <code>transferOwnership</code> runs immediately: moves git data on
  disk, updates <code>OwnerID</code>/<code>OwnerName</code>, re-recalculates collaborator access, and reassigns
  org-team repository links.</li>
<li><strong>Pending transfer</strong> (the common cross-account case) instead grants the recipient read access
  as a collaborator, sets <code>Status = RepositoryPendingTransfer</code>, and records a
  <code>repo_model.RepoTransfer</code> row; <code>notify_service.RepoPendingTransfer</code> notifies users who can
  accept/reject. The recipient later calls <code>AcceptTransferOwnership</code> (runs <code>transferOwnership</code>)
  or <code>RejectRepositoryTransfer</code> (clears the pending state, restores <code>RepositoryReady</code>).</li>
<li><code>CancelRepositoryTransfer</code> lets the <em>sender</em> abort a still-pending transfer.</li>
<li>While <code>Status == RepositoryPendingTransfer</code>, most write operations on the repo are blocked —
  it is neither fully "ready" nor "being migrated".</li>
</ul>
<h2 id="archive-unarchive">Archive / Unarchive<a href="#archive-unarchive" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Archiving is a simple boolean flag flip with lifecycle-wide consequences — it does <strong>not</strong> move
or delete any data. <code>routers/web/repo/setting/setting.go</code>'s <code>handleSettingsPostArchive</code> /
<code>handleSettingsPostUnarchive</code> handlers call <code>repo_model.SetArchiveRepoState(ctx, repo,
isArchived)</code> (<code>models/repo/archiver.go</code>), which sets <code>IsArchived</code> and stamps/clears
<code>ArchivedUnix</code>. Archiving is rejected for mirrors
(<code>repo.settings.archive.error_ismirror</code>) since a mirror's whole purpose is continued write
activity from upstream.</p>
<p>Once <code>IsArchived</code> is true, <code>Repository.MustNotBeArchived()</code> and numerous call sites across the
codebase (issue/PR creation, wiki edits, release creation, git push over HTTP/SSH, the API
<code>reqRepoWriter</code> gate in <code>routers/api/v1/api.go</code>) reject write operations — the repository becomes
effectively <strong>read-only</strong> while remaining fully browsable, clonable, and searchable.
Un-archiving (<code>SetArchiveRepoState(..., false)</code>) restores normal read/write behavior and
re-registers any Actions cron schedules that were suspended while archived.</p>
<h2 id="delete-deleterepositorydirectly">Delete — <code>DeleteRepositoryDirectly</code><a href="#delete-deleterepositorydirectly" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>services/repository/delete.go</code> performs a single large transaction that removes essentially
every row referencing the <code>RepoID</code> across the schema: access/collaboration records, issues,
comments, PRs, labels, milestones, commit statuses, branches/protected branches/tags, LFS locks,
language stats, license detections, mirrors and push-mirrors, notifications, releases, repo
units, stars/watches, webhooks (and their hook tasks), secrets, the full Actions object graph
(runs/jobs/tasks/artifacts/runners/schedules), and project links. Deploy keys are removed first
(<code>asymkey_service.DeleteRepoDeployKeys</code>), and if any were removed, <code>authorized_keys</code> is
rewritten after commit. Packages linked to the repo are unlinked (not deleted — packages can
outlive their originating repo). Only <strong>after</strong> the DB transaction commits does it remove
on-disk artifacts (git directory, wiki git directory, archives, LFS objects, attachments,
avatar) and queued log files, so a rolled-back transaction never leaves the repository without
its files. <code>DeleteOwnerRepositoriesDirectly</code> simply calls this in a loop for every repository
owned by a user/org being deleted.</p>
<h2 id="lifecycle-state-diagram">Lifecycle State Diagram<a href="#lifecycle-state-diagram" class="heading-anchor" aria-label="Link">#</a></h2>
<pre class="mermaid">stateDiagram-v2
    [*] --> BeingCreated: CreateRepositoryDirectly / ForkRepository / AdoptRepository / GenerateRepository
    BeingCreated --> Active: init/clone succeeds (Status = RepositoryReady)
    BeingCreated --> [*]: init/clone fails -> cleanupRepository (full rollback)

    [*] --> BeingMigrated: migrate/import request (Status = RepositoryBeingMigrated)
    BeingMigrated --> Active: MigrateRepositoryGitData succeeds, not a mirror
    BeingMigrated --> Mirror: MigrateRepositoryGitData succeeds, opts.Mirror = true
    BeingMigrated --> [*]: migration fails -> cleanupRepository

    Active --> Mirror: (rare) mirror conversion via re-migration
    Mirror --> Active: mirror settings removed / converted to normal repo

    Active --> Archived: SetArchiveRepoState(true) [not allowed while IsMirror]
    Archived --> Active: SetArchiveRepoState(false)

    Active --> PendingTransfer: StartRepositoryTransfer (cross-account, needs acceptance)
    PendingTransfer --> Active: AcceptTransferOwnership / RejectRepositoryTransfer / CancelRepositoryTransfer
    Active --> Active: StartRepositoryTransfer (direct transfer: admin, self, or org auto-accept)

    Mirror --> Mirror: scheduled/queued pull sync (services/mirror.SyncPullMirror)

    Active --> Deleted: DeleteRepositoryDirectly
    Mirror --> Deleted: DeleteRepositoryDirectly
    Archived --> Deleted: DeleteRepositoryDirectly

when its git data is found to be unusable, e.g. after a failed adoption check or a doctor-run
integrity failure; it is treated as permanently empty/unusable but is <em>not</em> automatically
deleted — an administrator must intervene (fix the git data out-of-band, or delete the

<h2 id="pull-push-mirroring-servicesmirror">Pull &amp; Push Mirroring — <code>services/mirror</code><a href="#pull-push-mirroring-servicesmirror" class="heading-anchor" aria-label="Link">#</a></h2>
<p>A repository created with <code>opts.Mirror = true</code> (via the migrate path above) keeps an active
<code>repo_model.Mirror</code> row and is continuously kept up to date by the mirror subsystem in
<code>services/mirror</code>. This is a distinct concern from <em>migration</em> (a one-time import): mirroring is
an ongoing background sync.</p>
<h3 id="sync-scheduling">Sync scheduling<a href="#sync-scheduling" class="heading-anchor" aria-label="Link">#</a></h3>
<ul>
<li>The cron task registered by <code>cron.registerUpdateMirrorTask</code>-style setup calls
  <code>mirror.Update(ctx, pullLimit, pushLimit)</code> (<code>services/mirror/mirror.go</code>), which iterates all
  due pull mirrors via <code>repo_model.MirrorsIterate</code> (rows where <code>next_update_unix &lt;= now</code>) and all
  due push mirrors via <code>repo_model.PushMirrorsIterate</code> (rows where <code>last_update + interval &lt;=
  now</code>, joined against <code>repository</code> to skip archived repos), pushing each into an in-memory,
  de-duplicating work queue (<code>queue.CreateUniqueQueue("mirror", ...)</code> in <code>services/mirror/queue.go</code>).</li>
<li><code>AddPullMirrorToQueue(repoID)</code> / <code>AddPushMirrorToQueue(mirrorID)</code> let other code paths
  (e.g. a manual "Synchronize Now" button, or <code>SyncOnCommit</code> push-mirrors right after a push is
  received) enqueue an immediate sync without waiting for the cron sweep.</li>
<li>The queue's worker (<code>queueHandler</code> → <code>doMirrorSync</code>) dispatches by <code>SyncRequest.Type</code> to
  <code>SyncPullMirror</code> or <code>SyncPushMirror</code>.</li>
</ul>
<h3 id="pull-mirrors-mirror_pullgo">Pull mirrors (<code>mirror_pull.go</code>)<a href="#pull-mirrors-mirror_pullgo" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>SyncPullMirror(ctx, repoID)</code>:</p>
<ol>
<li>Takes a per-repo lock (<code>repo_pull_mirror_&lt;id&gt;</code>) so concurrent syncs of the same repo never
   overlap.</li>
<li>Loads the <code>Mirror</code> row and re-validates the remote URL against SSRF allow/block rules on
   every sync (hosts can rebind between syncs).</li>
<li>Runs <code>git remote update</code>-equivalent fetch logic (<code>runSync</code>), pruning broken refs
   (<code>pruneBrokenReferences</code>) and tolerating a documented set of recoverable transient git errors
   (<code>checkRecoverableSyncError</code> — e.g. "cannot lock ref ... but expected", broken reference
   resolution) without failing the whole sync.</li>
<li>On success, reschedules (<code>Mirror.ScheduleNextUpdate()</code>, updates <code>LastSyncUnix</code>), then walks
   the fetch results to fire the same notifications a live push would generate
   (<code>notify_service.SyncPushCommits</code>, <code>SyncCreateRef</code>, <code>SyncDeleteRef</code>) so activity feeds,
   webhooks, and Actions triggers behave identically for mirror-driven and user-driven updates.</li>
<li>Handles the edge case of a mirror created against an originally-empty upstream that has since
   gained content (<code>checkAndUpdateEmptyRepository</code>), and re-queues the repository for license
   detection (<code>AddRepoToLicenseUpdaterQueue</code>).</li>
<li><code>UpdateAddress</code> lets an admin change the pull mirror's remote URL, re-pointing both the code
   remote and (if present) the wiki remote.</li>
</ol>
<h3 id="push-mirrors-mirror_pushgo">Push mirrors (<code>mirror_push.go</code>)<a href="#push-mirrors-mirror_pushgo" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Push mirrors are configured per-repository (a repo can have many <code>PushMirror</code> rows) and push
the <strong>local</strong> repository outward:</p>
<ul>
<li><code>AddPushMirrorRemote</code> / <code>RemovePushMirrorRemote</code> manage the underlying git remote and its
  <code>push</code> refspecs (<code>+refs/heads/*:refs/heads/*</code>, <code>+refs/tags/*:refs/tags/*</code>) for both the code
  repo and, if present, the wiki repo.</li>
<li><code>SyncPushMirror(ctx, mirrorID)</code> loads the <code>PushMirror</code> row, optionally uploads any LFS objects
  the remote is missing (<code>pushAllLFSObjects</code>, batched via the LFS batch API), then force-pushes
  with <code>--mirror</code> semantics (<code>gitrepo.PushToExternal(..., Mirror: true)</code>) through
  <code>runPushSync</code>. Errors are sanitized to strip credentials from URLs before being persisted to
  <code>PushMirror.LastError</code> (surfaced in the settings UI).</li>
<li><code>syncPushMirrorWithSyncOnCommit</code> is invoked from the post-receive/push path for any push
  mirror configured with <code>SyncOnCommit = true</code>, giving near-real-time mirroring instead of
  waiting for the next interval-based sweep.</li>
</ul>
<h3 id="where-mirrors-intersect-with-the-rest-of-the-lifecycle">Where mirrors intersect with the rest of the lifecycle<a href="#where-mirrors-intersect-with-the-rest-of-the-lifecycle" class="heading-anchor" aria-label="Link">#</a></h3>
<ul>
<li>A repository's <code>IsMirror</code> flag gates several safety checks: mirrors cannot be archived
  (<code>repo.settings.archive.error_ismirror</code>), and several settings-page mirror controls are hidden
  entirely when <code>setting.Mirror.Enabled</code> is false or the repo is archived
  (<code>routers/web/repo/setting/setting.go</code>).</li>
<li>Deleting a mirror repository (<code>DeleteRepositoryDirectly</code>) deletes its <code>Mirror</code> and
  <code>PushMirror</code> rows like any other satellite table — the remote upstream/downstream repositories
  are never touched.</li>
</ul>
