<h1>Storage, Queue & Caching</h1>
<h1 id="storage-queue-caching">Storage, Queue &amp; Caching</h1>
<p>Gitea's backend relies on three cross-cutting infrastructure modules that many higher-level
services depend on:</p>
<ul>
<li><strong><code>modules/storage</code></strong> — an abstraction over "blob" storage backends (local disk, MinIO/S3,
  Azure Blob) used for attachments, Git LFS objects, package files, avatars, archives, and
  Actions logs/artifacts.</li>
<li><strong><code>modules/queue</code></strong> — a generic, pluggable async job queue (in-memory channel, LevelDB-backed,
  or Redis-backed) used to decouple slow or bursty work (indexing, webhooks, mirrors, mail) from
  the request path.</li>
<li><strong><code>modules/cache</code></strong> — a thin wrapper around <code>gitea.com/go-chi/cache</code> (memory/two-queue LRU,
  Redis, Memcache) plus a request-scoped "ephemeral cache", used to avoid repeated expensive
  lookups (e.g. last commit info).</li>
</ul>
<p>A fourth related module, <strong><code>modules/globallock</code></strong>, provides distributed mutual exclusion
(in-memory or Redis via <code>redsync</code>) for operations that must not run concurrently across multiple
Gitea nodes (e.g. repository migration, packages that require read-modify-write semantics).</p>
<p>This page documents all four in detail.</p>
<h2 id="storage-backend-abstraction-modulesstorage">Storage Backend Abstraction (<code>modules/storage</code>)<a href="#storage-backend-abstraction-modulesstorage" class="heading-anchor" aria-label="Link">#</a></h2>
<h3 id="the-objectstorage-interface">The <code>ObjectStorage</code> Interface<a href="#the-objectstorage-interface" class="heading-anchor" aria-label="Link">#</a></h3>
<p>All storage backends implement a single common interface, defined in
<code>modules/storage/storage.go</code>:</p>
<pre class="highlight"><code class="language-go">// ObjectStorage represents an object storage to handle a bucket and files
type ObjectStorage interface {
    Open(path string) (Object, error)

    // Save store an object, if size is unknown set -1
    Save(path string, r io.Reader, size int64) (int64, error)

    Stat(path string) (os.FileInfo, error)
    Delete(path string) error

    // ServeDirectURL generates a "serve-direct" URL for the specified blob storage file,
    // end user (browser) will use this URL to access the file directly from the object
    // storage, bypassing the Gitea server. Usually time-limited and signed.
    ServeDirectURL(path, name, method string, opt *ServeDirectOptions) (*url.URL, error)

    // IterateObjects calls the iterator function for each object in the storage
    // with the given path as prefix
    IterateObjects(basePath string, iterator func(fullPath string, obj Object) error) error
}</code></pre>
<p>An <code>Object</code> returned by <code>Open</code> is a combination of <code>io.ReadCloser</code>, <code>io.Seeker</code>, and <code>Stat()</code>.</p>
<p>Helper functions built on top of this interface (in <code>helper.go</code> / <code>storage.go</code>) provide common
operations that work with any backend:</p>
<table>
<thead>
<tr>
<th>Function</th>
<th>Purpose</th>
</tr>

<h3 id="storage-configuration">Storage Configuration<a href="#storage-configuration" class="heading-anchor" aria-label="Link">#</a></h3>

<h2 id="queue-system-modulesqueue">Queue System (<code>modules/queue</code>)<a href="#queue-system-modulesqueue" class="heading-anchor" aria-label="Link">#</a></h2>
<h3 id="terminology">Terminology<a href="#terminology" class="heading-anchor" aria-label="Link">#</a></h3>
<p>The package doc comment in <code>modules/queue/queue.go</code> lays out the vocabulary used throughout the
module:</p>
<ul>
<li><strong>Item</strong> — a JSON-marshaled unit of work pushed onto a queue.</li>
<li><strong>Batch</strong> — a slice of items delivered together to a worker.</li>
<li><strong>Worker</strong> — a goroutine that calls the <code>Handler</code> on a batch.</li>
<li><strong>Handler</strong> (<code>HandlerFuncT[T]</code>) — <code>func(...T) (unhandled []T)</code>; any items returned as
  "unhandled" get pushed back onto the base queue after a short backoff, so a temporarily-down
  dependency (e.g. a search indexer) doesn't lose work.</li>
<li><strong>Base queue</strong> — the underlying storage mechanism: channel (in-memory), LevelDB
  (<code>levelqueue</code>), Redis, or <code>dummy</code> (no-op, used in tests / when a handler is nil).</li>
<li><strong>WorkerPoolQueue</strong> — glues a base queue to a pool of workers, exposing <code>Push</code>, <code>Has</code>,
  <code>FlushWithContext</code>, <code>ShutdownWait</code>.</li>
<li><strong>Manager</strong> — a process-wide registry of every <code>WorkerPoolQueue</code>, used by the admin "Monitor"
  page and by <code>FlushAll</code> (mainly for tests).</li>
</ul>
<pre class="highlight"><code class="language-go">type HandlerFuncT[T any] func(...T) (unhandled []T)</code></pre>
<p>A queue can additionally be <strong>unique</strong>, meaning duplicate items (by JSON-marshaled byte
equality) are rejected while already queued — <code>Has</code>/<code>HasItem</code> lets callers check this, though
the docs note it's "not 100% reliable" without real transactions.</p>

<h3 id="workerpoolqueue">WorkerPoolQueue<a href="#workerpoolqueue" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>modules/queue/workerqueue.go</code> defines the generic <code>WorkerPoolQueue[T]</code>, the type application
code actually interacts with. Key operations:</p>
<pre class="highlight"><code class="language-go">func (q *WorkerPoolQueue[T]) Push(data T) error {
    ...
    return q.baseQueue.PushItem(q.ctxRun, q.marshal(data))
}

func (q *WorkerPoolQueue[T]) Has(data T) (bool, error) {
    return q.baseQueue.HasItem(q.ctxRun, q.marshal(data))
}

func (q *WorkerPoolQueue[T]) Run()                              { q.doRun() }
func (q *WorkerPoolQueue[T]) Cancel()                            { q.ctxRunCancel() }
func (q *WorkerPoolQueue[T]) ShutdownWait(timeout time.Duration) { ... }
func (q *WorkerPoolQueue[T]) FlushWithContext(ctx context.Context, timeout time.Duration) error</code></pre>
<p><code>NewWorkerPoolQueueWithContext</code> wires the base queue, wraps the caller's <code>HandlerFuncT[T]</code> in a
<code>safeHandler</code> that recovers panics and restores <code>pprof</code> goroutine labels, and registers the
queue's lifetime with <code>process.GetManager()</code> (so it shows up in the process manager / <code>gitea
manager processes</code>). If <code>handler</code> is <code>nil</code>, the queue type is forced to <code>dummy</code> — this is used
when a caller just wants a <code>Push</code>-able sink without actually processing items (typically tests).</p>
<p><code>workergroup.go</code> implements the actual dynamic worker pool: <code>doDispatchBatchToWorker</code> batches
popped items (<code>batchLength</code>), and spins up new workers (up to <code>workerMaxNum</code>) only when the
batch channel would otherwise block or there are zero active workers — this avoids the cost of
running <code>MaxWorkers</code> goroutines when the queue is idle.</p>
<pre class="highlight"><code class="language-go">func (q *WorkerPoolQueue[T]) doWorkerHandle(batch []T) {
    ...
    unhandled := q.safeHandler(batch...)
    if len(unhandled) == len(batch) &amp;&amp; unhandledItemRequeueDuration.Load() != 0 {
        // back off before requeueing, e.g. indexer is temporarily down
        ...
    }
    for _, item := range unhandled {
        if err := q.Push(item); err != nil {
            ...
        }
    }
}</code></pre>
<p>On shutdown (<code>ShutdownWait</code>), any items still in flight or in the batch buffer are pushed back
into the base queue via <code>basePushForShutdown</code> within a bounded <code>shutdownTimeout</code>, so in-memory
"channel" queues don't silently lose work on restart (persistent backends like LevelDB/Redis
retain them naturally).</p>

<p><code>modules/indexer/issues/indexer.go</code> is a representative example. It defines a small metadata
struct sent through the queue (not the whole issue, to keep messages small):</p>
<pre class="highlight"><code class="language-go">type IndexerMetadata struct {

    IsDelete bool    `json:"is_delete"`
    IDs      []int64 `json:"ids"`

<p>Whenever an issue changes, calling code pushes an <code>IndexerMetadata</code> onto <code>issueIndexerQueue</code>.
Workers pop batches and forward them to <code>getIssueIndexerQueueHandler</code>, which resolves each ID
against the DB and calls the underlying search backend's <code>Index</code>/<code>Delete</code>. If the backend isn't
ready (e.g. still initializing), the handler returns the batch as "unhandled" and the queue
requeues it after a short backoff — the push path never blocks on indexing being available.</p>

<h2 id="caching-layer-modulescache">Caching Layer (<code>modules/cache</code>)<a href="#caching-layer-modulescache" class="heading-anchor" aria-label="Link">#</a></h2>
<h3 id="stringcache-and-giteacomgo-chicache"><code>StringCache</code> and <code>gitea.com/go-chi/cache</code><a href="#stringcache-and-giteacomgo-chicache" class="heading-anchor" aria-label="Link">#</a></h3>
<p>Gitea wraps the upstream <code>gitea.com/go-chi/cache</code> package (itself supporting <code>memory</code>,
<code>twoqueue</code>, <code>redis</code>, and <code>memcache</code> adapters) behind a typed <code>StringCache</code> interface
(<code>modules/cache/string_cache.go</code>):</p>
<pre class="highlight"><code class="language-go">type StringCache interface {
    Ping() error

    Get(key string) (string, bool)
    Put(key, value string, ttl int64) error
    Delete(key string) error
    IsExist(key string) bool

    PutJSON(key string, v any, ttl int64) error

<p><code>PutJSON</code>/<code>GetJSON</code> marshal arbitrary values to/from JSON strings so any struct can be cached

<p><code>modules/cache/cache.go</code> initializes the process-wide default cache:</p>
<pre class="highlight"><code class="language-go">var defaultCache StringCache

    if defaultCache == nil {
        c, err := NewStringCache(setting.CacheService.Cache)
        ...
        defaultCache = c
    }
    return nil
}

func GetString(key string, getFunc func() (string, error)) (string, error) {
    if defaultCache == nil || setting.CacheService.TTL == 0 {
        return getFunc()
    }
    cached, exist := defaultCache.Get(key)
    if !exist {
        value, err := getFunc()
        ...
        return value, defaultCache.Put(key, value, setting.CacheService.TTLSeconds())
    }
    return cached, nil

<p><code>GetString</code>/<code>GetInt64</code> implement the classic "cache-aside" pattern: check the cache, and on miss
call the provided <code>getFunc</code>, store the result, and return it. <code>setting.CacheService</code> also
configures a dedicated <code>LastCommit</code> sub-cache (<code>[cache.last_commit]</code>, default 1 year TTL,
tracked per-<code>CommitsCount</code>) used to memoize "last commit info" for directory listings, a
notoriously expensive Git operation on large repositories.</p>
<h3 id="ephemeral-request-scoped-cache">Ephemeral (Request-Scoped) Cache<a href="#ephemeral-request-scoped-cache" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>modules/cache/context.go</code> and <code>modules/cache/ephemeral.go</code> implement a short-lived,
in-memory-only cache attached to a <code>context.Context</code>, distinct from the shared <code>StringCache</code>:</p>
<pre class="highlight"><code class="language-go">func WithCacheContext(ctx context.Context) context.Context {
    if c := GetContextCache(ctx); c != nil {
        return ctx
    }
    return context.WithValue(ctx, cacheContextKey, NewEphemeralCache(contextCacheLifetime))
}

func GetWithContextCache[T, K any](ctx context.Context, groupKey string, targetKey K,
    f func(context.Context, K) (T, error)) (T, error) {
    if c := GetContextCache(ctx); c != nil {
        return GetWithEphemeralCache(ctx, c, groupKey, targetKey, f)
    }
    return f(ctx, targetKey)
}</code></pre>
<p><code>EphemeralCache</code> self-limits to a 5-minute (<code>contextCacheLifetime</code>) lifetime and logs a warning
if it's queried past that — it exists purely to deduplicate repeated lookups <em>within a single
request</em> (e.g. resolving the same user or repo multiple times while rendering a page), not as a
general-purpose cache; using it beyond a request's lifetime is explicitly discouraged in the
source comments.</p>

<h2 id="global-distributed-locking-modulesgloballock">Global Distributed Locking (<code>modules/globallock</code>)<a href="#global-distributed-locking-modulesgloballock" class="heading-anchor" aria-label="Link">#</a></h2>
<p>While the queue and cache systems help with <em>async work</em> and <em>avoiding repeated work</em>, some
operations must be serialized across the entire cluster — e.g. mutating a Git repository's
config file, transferring repository ownership, or pushing to a container image manifest.
<code>modules/globallock</code> provides that guarantee.</p>
<h3 id="locker-interface"><code>Locker</code> Interface<a href="#locker-interface" class="heading-anchor" aria-label="Link">#</a></h3>
<pre class="highlight"><code class="language-go">type Locker interface {
    // Lock blocks until the lock is acquired or ctx is canceled.
    Lock(ctx context.Context, key string) (ReleaseFunc, error)

    // TryLock returns immediately; returns (false, release, nil) if already locked
    // (as opposed to some other error like Redis being down).
    TryLock(ctx context.Context, key string) (bool, ReleaseFunc, error)
}

type ReleaseFunc func()</code></pre>
<p><code>ReleaseFunc</code> is always non-nil and idempotent-safe to call, even if lock acquisition failed —
callers are expected to always <code>defer release()</code>.</p>

<h2 id="how-the-three-systems-interact">How the Three Systems Interact<a href="#how-the-three-systems-interact" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Storage, queue, and cache are largely independent, but they compose in real features. A common
pattern (e.g. repository archive generation in <code>services/repository/archiver/archiver.go</code>) is:</p>
<ol>
<li>A web request enqueues a job onto a <code>WorkerPoolQueue</code> (queue system) instead of doing
   expensive work synchronously.</li>
<li>A worker picks up the job, does the work, and writes the result into an <code>ObjectStorage</code>
   backend (storage system) — e.g. <code>storage.RepoArchives</code>.</li>
<li>Subsequent requests for the same result use <code>cache.GetString</code>/<code>GetWithContextCache</code> (cache
   system) to avoid re-checking storage or re-querying the DB for status on every poll, and/or
   use <code>globallock</code> to make sure only one worker builds a given archive at a time.</li>
</ol>
<pre class="mermaid">flowchart TD
    Req["HTTP Request"] --> Check{"Cached result?"}
    Check -- yes --> Resp["Return cached response"]
    Check -- no --> Lock["globallock.TryLock(key)"]
    Lock -- locked by another node --> Wait["Return 'in progress' status"]
    Lock -- acquired --> Enqueue["queue.Push(job)"]
    Enqueue --> Worker["Queue worker executes job"]
    Worker --> Save["storage.Save(path, data)"]
    Save --> CacheSet["cache.Put(key, result, ttl)"]
    CacheSet --> Resp2["Serve result / ServeDirectURL"]</pre>

      var item=idx[i];var score=0;
      if(item.t.toLowerCase().indexOf(q)>=0)score+=10;
      for(var j=0;j<item.h.length;j++){if(item.h[j].toLowerCase().indexOf(q)>=0)score+=3;}
      if(score>0)hits.push({item:item,score:score});
    }
    hits.sort(function(a,b){return b.score-a.score;});
    var html='';
    for(var k=0;k<Math.min(hits.length,15);k++){
      var h=hits[k].item;
      html+='<a href="'+prefix+h.p+'">'+h.t+'</a>';
      var mh=[];for(var m=0;m<h.h.length;m++){if(h.h[m].toLowerCase().indexOf(q)>=0)mh.push(h.h[m]);}
      for(var n=0;n<Math.min(mh.length,2);n++){html+='<div class="search-heading">↳ '+mh[n]+'</div>';}
    }
    if(!hits.length)html='<div style="padding:8px 12px;color:var(--text-dim);font-size:0.8rem">No results</div>';
    searchResults.innerHTML=html;
  });
})();

        overlayInner.appendChild(clone);

        overlay.classList.add('open');

        setTimeout(function(){
          if(window.mermaid){
            try{mermaid.run({nodes:[clone]});}catch(err){}
          }
        },50);
      });
      wrapper.appendChild(btn);
    });
  }
  // Wait for mermaid to finish rendering before adding buttons (mermaid init runs above)
  setTimeout(_addMermaidButtons,800);
  if(overlay){
    overlay.addEventListener('click',function(e){if(e.target===overlay)overlay.classList.remove('open');});
    document.addEventListener('keydown',function(e){if(e.key==='Escape')overlay.classList.remove('open');});
  }
  // Code copy buttons
  document.querySelectorAll('pre').forEach(function(pre){
    if(pre.classList.contains('mermaid'))return;
    var btn=document.createElement('button');
    btn.className='code-copy';btn.textContent='Copy';
    btn.addEventListener('click',function(){
      var code=pre.querySelector('code');
      var text=code?code.textContent:pre.textContent;
      navigator.clipboard.writeText(text).then(function(){btn.textContent='Copied!';setTimeout(function(){btn.textContent='Copy';},2000);});

    var tocAside=document.querySelector('.toc-aside');
    var onScroll=function(){
      var scrollPos=window.scrollY+80;
      var active=null;
      for(var i=0;i<headingEls.length;i++){if(headingEls[i].el.offsetTop<=scrollPos)active=headingEls[i];}
      tocLinks.forEach(function(l){l.classList.remove('toc-active');});

          var visibleTop=tocAside.scrollTop;

          if(linkTop<visibleTop+40||linkTop>visibleBottom-40){

      var linkOffset=activeLink.offsetTop-sidebarEl.offsetTop;
      sidebarEl.scrollTop=Math.max(0,linkOffset-sidebarEl.clientHeight/2);
    }
  }
})();
