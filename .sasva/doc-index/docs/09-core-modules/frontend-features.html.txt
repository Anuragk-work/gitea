<h1>Frontend Features & the "Islands of Interactivity" Pattern</h1>
<h1 id="frontend-features-the-islands-of-interactivity-pattern">Frontend Features &amp; the "Islands of Interactivity" Pattern</h1>
<p>Gitea's UI is fundamentally <strong>server-rendered</strong>: every page's HTML comes from Go's
<code>html/template</code> engine (see <code>templates/**/*.tmpl</code>). The frontend TypeScript/Vue code in
<code>web_src/js/</code> does not take over routing or rendering — instead it <em>progressively enhances</em>
already-rendered HTML by attaching event listeners, mounting small Vue components into specific
DOM nodes, and reacting to DOM mutations. This page catalogs the ~80 feature modules under
<code>web_src/js/features/</code>, the Vue <code>components/</code>, the custom <code>webcomponents/</code>, the Markdown/markup
live-preview pipeline, and explains the "islands of interactivity" architecture that ties them
all together. For the build tooling that compiles all of this, see
<a href="frontend-build.html">Frontend Build Pipeline</a>.</p>
<h2 id="the-islands-of-interactivity-pattern">The Islands of Interactivity Pattern<a href="#the-islands-of-interactivity-pattern" class="heading-anchor" aria-label="Link">#</a></h2>
<p>Rather than a single-page app that owns the whole DOM, Gitea's frontend is organized as many
small, independent "islands": isolated pieces of interactive behavior that attach themselves to
specific elements already present in server-rendered HTML. Three mechanisms implement this.</p>
<h3 id="1-global-init-functions-called-once-at-page-load">1. Global init functions, called once at page load<a href="#1-global-init-functions-called-once-at-page-load" class="heading-anchor" aria-label="Link">#</a></h3>
<p><code>web_src/js/index.ts</code> is the single entry bundle loaded on every page. It imports ~70 named
<code>init*</code> functions from <code>features/*.ts</code> and passes them as an array to <code>callInitFunctions()</code>
(defined in <code>web_src/js/modules/init.ts</code>):</p>
<pre class="highlight"><code class="language-ts">// web_src/js/index.ts (excerpt)
import {initDashboardRepoList} from './features/dashboard.ts';
import {initHeatmap} from './features/heatmap.ts';
import {initRepoDiffView} from './features/repo-diff.ts';
import {initRepoEditor} from './features/repo-editor.ts';
import {initUserAuthWebAuthn, initUserAuthWebAuthnRegister} from './features/user-auth-webauthn.ts';
// ...

const initPerformanceTracer = callInitFunctions([
  initGiteaFomantic,
  initGlobalComponent, initGlobalDropdown, initGlobalFetchAction, initGlobalTooltips,
  // ...
  initHeatmap, initImageDiff, initRepoDiffView, initRepoEditor,
  initUserAuthWebAuthn, initUserAuthWebAuthnRegister,
  // ...
]);
initGlobalSelectorObserver(initPerformanceTracer);</code></pre>
<p>Each <code>init*</code> function is responsible for finding its own root element(s) — typically via
<code>document.querySelector</code> — and returning immediately (a no-op) if that element isn't present on
the current page:</p>
<pre class="highlight"><code class="language-ts">// web_src/js/features/heatmap.ts (excerpt)
export async function initHeatmap() {
  const el = document.querySelector&lt;HTMLElement&gt;('#user-heatmap');
  if (!el) return;
  // ... fetch data, dynamically import the Vue component, mount it
}</code></pre>
<p>This means every page pays only the (very small) cost of running a <code>querySelector</code> for features
irrelevant to it — there's no router or page-type dispatch table; every module self-selects.
<code>window.config.frontendInited = true</code> is set once all init functions and the selector observer
have run, giving both humans and E2E tests (Playwright) a reliable signal that hydration is
complete. <code>?_ui_performance_trace=1</code> in the URL enables <code>InitPerformanceTracer</code>, which times each
init function and each selector-scan and logs the slowest 20 to the console — useful for
regressions where a single <code>init*</code> function blocks the main thread.</p>
<h3 id="2-declarative-data-global-init-data-global-click-attributes">2. Declarative <code>data-global-init</code> / <code>data-global-click</code> attributes<a href="#2-declarative-data-global-init-data-global-click-attributes" class="heading-anchor" aria-label="Link">#</a></h3>
<p>For features that need to run not just once at page load but also whenever <em>new</em> matching
elements are inserted into the DOM later (e.g. after an AJAX partial reload, or content added via
<code>innerHTML</code>), Gitea uses a <code>MutationObserver</code>-backed registry in <code>web_src/js/modules/observer.ts</code>:</p>
<pre class="highlight"><code class="language-ts">export function registerGlobalInitFunc&lt;T extends HTMLElement&gt;(name: string, handler: GlobalInitFunc&lt;T&gt;) {
  globalInitFuncs[name] = handler as GlobalInitFunc&lt;Element&gt;;
}
export function registerGlobalSelectorFunc&lt;T extends Element&gt;(selector: string, handler: (el: T) =&gt; void) {
  selectorHandlers.push({selector, handler: handler as (el: Element) =&gt; void});
}
export function registerGlobalEventFunc&lt;T extends HTMLElement, E extends Event&gt;(event: string, name: string, func: GlobalEventFunc&lt;T, E&gt;) {
  globalEventFuncs[`${event}:${name}`] = func as GlobalEventFunc&lt;HTMLElement, Event&gt;;
}</code></pre>
<p><code>initGlobalSelectorObserver()</code> (called last, after all <code>init*</code> functions have registered their
handlers) does one <code>querySelectorAll</code> per registered selector over the whole document, then sets
up a single <code>MutationObserver</code> that re-runs the matching handler for any element added later
anywhere in the page. Server templates opt an element into this system just by adding an
attribute — no JS import needed at the template layer:</p>
<pre class="highlight"><code class="language-html">&lt;!-- templates/repo/settings/actions_general.tmpl --&gt;
&lt;form class="ui form" data-global-init="initRepoActionsPermissionsForm"&gt;...&lt;/form&gt;

&lt;!-- templates/repo/latest_commit.tmpl --&gt;
&lt;button class="ui button ellipsis-button" data-global-click="onRepoEllipsisButtonClick"&gt;...&lt;/button&gt;

&lt;!-- templates/repo/view_file.tmpl --&gt;
&lt;a class="btn-octicon" data-global-click="onCopyContentButtonClick" ...&gt;</code></pre>
<p>Corresponding TS registers the handler once, by name, and the observer wires it to every current
and future matching element automatically:</p>
<pre class="highlight"><code class="language-ts">// web_src/js/features/common-actions-permissions.ts
registerGlobalInitFunc('initRepoActionsPermissionsForm', initActionsPermissionsFormInner);</code></pre>
<p>This attribute-based dispatch means backend template authors can add new interactive behavior to
server-rendered HTML by adding one attribute, without needing to add a <code>querySelector</code>-based
<code>init*</code> function to <code>index.ts</code> at all — as long as the handler name is already registered
somewhere in a loaded module.</p>
<h3 id="3-vue-components-mounted-onto-specific-elements-islands">3. Vue components mounted onto specific elements ("islands")<a href="#3-vue-components-mounted-onto-specific-elements-islands" class="heading-anchor" aria-label="Link">#</a></h3>
<p>For anything with non-trivial client-side state (heatmaps, diff file trees, action run logs,
branch selectors, etc.), a feature module dynamically imports a <code>.vue</code> single-file component and
mounts a whole isolated Vue app instance directly onto the server-rendered placeholder element:</p>
<pre class="highlight"><code class="language-ts">// web_src/js/features/heatmap.ts
const {default: ActivityHeatmap} = await import('../components/ActivityHeatmap.vue');
const View = createApp(ActivityHeatmap, {values, locale});
View.mount(el);
el.classList.remove('is-loading');</code></pre>
<pre class="highlight"><code class="language-ts">// web_src/js/features/ref-issue.ts — an app that can also unmount itself
const app = createApp(ContextPopup, {...});
app.mount(el);
// later, e.g. on tippy.js popup hide:
onDestroy: () =&gt; app.unmount(),</code></pre>
<p>Each such mount is its own independent Vue application instance — there is no single root Vue
app for the whole page. Data typically flows in via <code>data-*</code> HTML attributes read by the
surrounding <code>init*</code> function, or via <code>window.config.pageData</code> (see
<code>web_src/js/globals.d.ts</code> for the full shape, e.g. <code>pageData.citationFileContent</code>,
<code>pageData.DiffFileTree</code>, <code>pageData.repoActivityTopAuthors</code>), and is passed to the component as
Vue <code>props</code>.</p>
<pre class="mermaid">flowchart TD
    A["Go html/template renders full page HTML<br/>(templates/**/*.tmpl)"] --> B["Browser loads page + index.js bundle"]
    B --> C["callInitFunctions() runs ~70 init* functions<br/>(modules/init.ts)"]
    C --> D{"Root element present?<br/>document.querySelector(...)"}
    D -- no --> E["no-op, return"]
    D -- yes --> F["Attach listeners / mount Vue component<br/>createApp(Component, props).mount(el)"]
    C --> G["initGlobalSelectorObserver()<br/>(modules/observer.ts)"]
    G --> H["querySelectorAll for every registered selector<br/>+ data-global-init / data-global-click"]
    H --> I["MutationObserver watches for future DOM insertions<br/>(AJAX partials, dynamic content)"]
    I -.new nodes added later.-> H</pre>

<h2 id="why-this-architecture">Why This Architecture<a href="#why-this-architecture" class="heading-anchor" aria-label="Link">#</a></h2>
<p>This design keeps Gitea's frontend footprint small and the backend/frontend coupling loose:</p>
<ul>
<li><strong>No client-side router</strong> — every navigation is a normal full-page load handled by Go's router
  (see <a href="../06-web-routers/README.html">Web Routers</a>); the frontend never needs to reconstruct page
  state from an API, because the HTML already contains it.</li>
<li><strong>Incremental adoption of Vue</strong> — new complex widgets can be written as Vue SFCs without
  requiring a rewrite of surrounding legacy Fomantic/jQuery-influenced markup; old and new code
  co-exist page by page, even within the same page.</li>
</ul>
