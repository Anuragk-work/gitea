<h1>Webhook Event Types & Payloads</h1>
<h1 id="webhook-event-types-payloads">Webhook Event Types &amp; Payloads</h1>
<p>This page documents Gitea's outgoing-webhook event vocabulary (<code>HookEventType</code>), how a
webhook's subscription to a subset of events is modeled, and the exact JSON payload schema
sent for each event family. It is verified against <code>modules/webhook/type.go</code>,
<code>modules/webhook/events.go</code>, <code>models/webhook/webhook.go</code>, and <code>modules/structs/hook.go</code>.</p>
<h2 id="event-types-hookeventtype">Event types (<code>HookEventType</code>)<a href="#event-types-hookeventtype" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>modules/webhook/type.go</code> defines every event a webhook can subscribe to:</p>
<pre class="highlight"><code class="language-go">type HookEventType string

const (
    HookEventCreate                    HookEventType = "create"
    HookEventDelete                    HookEventType = "delete"
    HookEventFork                      HookEventType = "fork"
    HookEventPush                      HookEventType = "push"
    HookEventIssues                    HookEventType = "issues"
    HookEventIssueAssign               HookEventType = "issue_assign"
    HookEventIssueLabel                HookEventType = "issue_label"
    HookEventIssueMilestone            HookEventType = "issue_milestone"
    HookEventIssueComment              HookEventType = "issue_comment"
    HookEventPullRequest               HookEventType = "pull_request"
    HookEventPullRequestAssign         HookEventType = "pull_request_assign"
    HookEventPullRequestLabel          HookEventType = "pull_request_label"
    HookEventPullRequestMilestone      HookEventType = "pull_request_milestone"
    HookEventPullRequestComment        HookEventType = "pull_request_comment"
    HookEventPullRequestReviewApproved HookEventType = "pull_request_review_approved"
    HookEventPullRequestReviewRejected HookEventType = "pull_request_review_rejected"
    HookEventPullRequestReviewComment  HookEventType = "pull_request_review_comment"
    HookEventPullRequestSync           HookEventType = "pull_request_sync"
    HookEventPullRequestReviewRequest  HookEventType = "pull_request_review_request"
    HookEventWiki                      HookEventType = "wiki"
    HookEventRepository                HookEventType = "repository"
    HookEventRelease                   HookEventType = "release"
    HookEventPackage                   HookEventType = "package"
    HookEventStatus                    HookEventType = "status"

    HookEventPullRequestReview HookEventType = "pull_request_review" // grouping value, see below

    // Actions event only
    HookEventSchedule    HookEventType = "schedule"
    HookEventWorkflowRun HookEventType = "workflow_run"
    HookEventWorkflowJob HookEventType = "workflow_job"
)</code></pre>
<p><code>AllEvents()</code> returns the flat list used to populate "Send Everything" and the individual event
checkboxes in the webhook settings UI/API. Several of these are <strong>sub-events</strong> that share a
payload shape with a "parent" event but exist so the UI can offer more granular triggers (e.g.
"only notify when an issue is assigned" vs. "notify for every issue change"). <code>Event()</code>
collapses a <code>HookEventType</code> down to the normalized event name used in HTTP headers and in
<code>payloadConvertor</code> dispatch:</p>
<table>
<thead>

<h2 id="subscribing-a-webhook-to-events-hookevent">Subscribing a webhook to events (<code>HookEvent</code>)<a href="#subscribing-a-webhook-to-events-hookevent" class="heading-anchor" aria-label="Link">#</a></h2>
<p>A <code>Webhook</code> row's subscription is stored as JSON in its <code>Events</code> column and unmarshaled into
<code>*webhook_module.HookEvent</code> on load (<code>Webhook.AfterLoad</code>):</p>
<pre class="highlight"><code class="language-go">// modules/webhook/events.go
type HookEvents map[HookEventType]bool

type HookEvent struct {
    PushOnly       bool   `json:"push_only"`
    SendEverything bool   `json:"send_everything"`
    ChooseEvents   bool   `json:"choose_events"`
    BranchFilter   string `json:"branch_filter"`

    HookEvents `json:"events"`
}</code></pre>
<p><code>Webhook.HasEvent(evt)</code> is the single gate consulted by <code>PrepareWebhook</code> (see
<a href="webhook-delivery-pipeline.html#step-4-webhook-matching--gating-preparewebhooks--preparewebhook">Webhook Delivery Pipeline</a>):</p>
<pre class="highlight"><code class="language-go">func (w *Webhook) HasEvent(evt webhook_module.HookEventType) bool {
    if w.SendEverything {
        return true
    }
    if w.PushOnly {
        return evt == webhook_module.HookEventPush
    }
    checkEvt := evt
    switch evt {
    case webhook_module.HookEventPullRequestReviewApproved,
        webhook_module.HookEventPullRequestReviewRejected,
        webhook_module.HookEventPullRequestReviewComment:
        checkEvt = webhook_module.HookEventPullRequestReview
    }
    return w.HookEvents[checkEvt]
}</code></pre>
<p>Note the special-case remap for the three PR-review sub-events: the webhook settings UI exposes
a single "Pull Request Review" checkbox (<code>HookEventPullRequestReview</code>) rather than three
separate ones, so <code>HasEvent</code> normalizes any of the three concrete review events back to that
one key before checking the persisted <code>HookEvents</code> map. <code>BranchFilter</code> (a glob, e.g. <code>main</code> or
<code>release/*</code>) additionally restricts delivery to ref-bearing events (<code>push</code>, <code>create</code>, <code>delete</code>)
whose ref matches the pattern — see <code>checkBranchFilter</code> in
<a href="webhook-delivery-pipeline.html">Webhook Delivery Pipeline</a>.</p>
<p><code>EventsArray()</code> is the reverse projection — turning the stored subscription back into a flat
list of event-name strings, used when serializing a <code>Webhook</code> for the REST API (<code>api.Hook</code>).</p>
