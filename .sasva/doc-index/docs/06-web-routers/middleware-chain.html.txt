<h1>Middleware Chain: Sessions, CSRF/Origin Protection, and the Auth Context</h1>
<h1 id="middleware-chain-sessions-csrforigin-protection-and-the-auth-context">Middleware Chain: Sessions, CSRF/Origin Protection, and the Auth Context</h1>
<p>This page traces exactly how a web request acquires a session, gets its
<code>*context.Context</code> built, gets authenticated, and gets protected against
cross-origin/CSRF attacks, by following the middlewares registered in
<code>routers/web/web.go</code>, <code>routers/common/middleware.go</code>, <code>routers/common/auth.go</code>, and
<code>services/context/context.go</code>.</p>
<h2 id="ordering-overview">Ordering overview<a href="#ordering-overview" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>routers.NormalRoutes()</code> installs a first layer of protocol-level middlewares via
<code>common.ProtocolMiddlewares()</code>, then mounts the web UI router, which installs a second,
web-UI-specific layer. Put together, a request to a normal web UI page flows through
these middlewares, strictly in this order:</p>
<pre class="mermaid">graph TD
  A["chi_middleware.GetHead<br/>(HEAD→GET fallback)"] --> B["ChiRoutePathHandler<br/>fix RoutePath from RawPath"]
  B --> C["RequestContextHandler<br/>new reqctx.RequestContext + panic recovery"]
  C --> D["SecurityHeadersHandler<br/>X-Content-Type-Options, X-Frame-Options"]
  D --> E["ForwardedHeadersHandler<br/>(if ReverseProxyLimit > 0)"]
  E --> F["routing.NewRequestInfoHandler<br/>route/perf tracing"]
  F --> G["context.AccessLogger<br/>(if access log enabled)"]
  G --> H["public.ViteDevMiddleware<br/>(dev builds only)"]
  H --> I["common.MaintenanceModeHandler<br/>(AfterRouting, outermost of web UI mount)"]
  I --> J["gzhttp wrapper<br/>(if EnableGzip)"]
  J --> K["common.MustInitSessioner<br/>chi-session cookie/store"]
  K --> L["context.Contexter<br/>builds *context.Context, flash, PageData"]
  L --> M["AuthMiddleware.MiddlewareHandler<br/>auth_service.Group: OAuth2\u2192Basic\u2192ReverseProxy\u2192Session\u2192SSPI"]
  M --> N["goGet<br/>go-get=1 short-circuit"]
  N --> O["common.PageGlobalData"]
  O --> P["common.BlockExpensive / common.QoS"]
  P --> Q["per-route guards<br/>reqSignIn / reqUnitAccess / feature flags"]
  Q --> R["verifyAuthWithOptions<br/>prohibited-login, must-change-password, sign-in/out enforcement, CrossOriginProtection.Check"]
  R --> S["handler"]</pre>
<h2 id="1-protocol-level-middlewares-routerscommonmiddlewarego">1. Protocol-level middlewares (<code>routers/common/middleware.go</code>)<a href="#1-protocol-level-middlewares-routerscommonmiddlewarego" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>ProtocolMiddlewares()</code> runs first, for <em>every</em> route mounted under <code>NormalRoutes()</code>
(web UI, REST API, internal API, packages, actions):</p>
<table>
<thead>
<tr>
<th>Middleware</th>
<th>Purpose</th>
</tr>
</thead>

<h2 id="2-session-middleware-commonmustinitsessioner">2. Session middleware (<code>common.MustInitSessioner</code>)<a href="#2-session-middleware-commonmustinitsessioner" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>MustInitSessioner()</code> wraps <a href="https://gitea.com/go-chi/captcha"><code>go-chi/session</code></a> using
<code>setting.SessionConfig</code> (<code>Provider</code>, <code>ProviderConfig</code>, <code>CookieName</code>, <code>CookiePath</code>,
<code>Gclifetime</code>, <code>Maxlifetime</code>, <code>Secure</code>, <code>SameSite</code>, <code>Domain</code>). It is only added to the
web UI's inner <code>mid</code> slice (not the REST or internal API), because those use bearer
tokens/<code>INTERNAL_TOKEN</code> instead of cookie sessions. <code>IgnoreReleaseForWebSocket: true</code>
means a websocket handler is responsible for managing its own session release rather
than relying on the middleware's implicit release-on-response.</p>
<p>Note the code comment <code>CHI-SESSION-GOB-REGISTER</code>: any package that stores custom
struct types in the session must call <code>gob.Register</code> for those types during package
init, otherwise decoding a previously-stored session after a server restart will fail
silently.</p>
<h2 id="3-context-construction-contextcontexter">3. Context construction (<code>context.Contexter</code>)<a href="#3-context-construction-contextcontexter" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>context.Contexter()</code> (in <code>services/context/context.go</code>) is the single middleware that
turns a raw <code>*http.Request</code> into Gitea's <code>*context.Context</code>:</p>
<ul>
<li>Builds <code>Base</code> (the low-level request/response wrapper) via <code>NewBaseContext</code>.</li>
<li>Builds the full <code>*context.Context</code> via <code>NewWebContext(base, rnd, session.GetContextSession(req))</code>,
  which sets up <code>ctx.Render</code>, <code>ctx.Session</code>, <code>ctx.Cache</code>, <code>ctx.Link</code>, <code>ctx.Repo</code>,
  <code>ctx.Org</code>, and the Go-template <code>TemplateContext</code> (avatar/render/misc/actions
  template helpers, <code>Consts</code> map of repo unit type IDs).</li>
<li>Merges common template data (<code>middleware.CommonTemplateContextData()</code>), the current
  URL, and an (initially empty) <code>PageData</code> map that is later serialized into
  <code>window.config.pageData</code> for frontend JS.</li>
<li>Reads the last flash message from a signed cookie (<code>CookieNameFlash</code>) and registers
  a <code>ctx.Resp.Before(...)</code> hook to write any <em>new</em> flash message back to that cookie
  before the response is sent.</li>
<li>For <code>POST</code> requests with <code>multipart/form-data</code>, calls <code>ctx.ParseMultipartForm()</code>
  eagerly — the code comment <code>GLOBAL-PARSE-FORM</code> explains this is a legacy holdover
  from when CSRF tokens needed to be extracted from multipart bodies; Gitea has since
  dropped the old CSRF-token mechanism in favor of <code>http.CrossOriginProtection</code>
  (see §5 below), but the eager multipart parsing remains because some handlers rely
  on form values being pre-parsed.</li>
<li>Sets cache-control headers, <code>SystemConfig</code>, <code>ShowTwoFactorRequiredMessage</code>,
  <code>DisableMigrations</code>/<code>DisableStars</code>/<code>EnableActions</code> template flags, and <code>AllLangs</code>.</li>
</ul>
<p>The install-page variant, <code>context.ContexterInstallPage(data map[string]any)</code>, is a
stripped-down version used only by <code>routers/install</code> (no auth, no flash cookie, no
multipart handling) — see <a href="install-and-private.html">Install &amp; Private Routers</a>.</p>
<h2 id="4-authentication-authmiddleware">4. Authentication (<code>AuthMiddleware</code>)<a href="#4-authentication-authmiddleware" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>newWebAuthMiddleware()</code> (in <code>routers/web/web.go</code>) returns an <code>AuthMiddleware</code> with
three fields:</p>
<pre class="highlight"><code class="language-go">type AuthMiddleware struct {
    AllowOAuth2       types.PreMiddlewareProvider
    AllowBasic        types.PreMiddlewareProvider
    MiddlewareHandler func(*context.Context)
}</code></pre>
<p><code>AllowBasic</code>/<code>AllowOAuth2</code> are tiny middlewares that stash a boolean flag in the
request's <code>reqctx</code> data store (via private context-key types, so no other package can
set them). Individual route groups opt in by listing <code>webAuth.AllowBasic</code> and/or
<code>webAuth.AllowOAuth2</code> as extra middlewares — this is how routes like git-over-HTTP, RSS
feeds, and OAuth2 token endpoints support non-browser/non-session clients while the
rest of the site only accepts the session cookie.</p>
<p><code>MiddlewareHandler</code> is installed once, globally, in the web UI's middleware chain (so
it always runs and always determines <code>ctx.Doer</code>/<code>ctx.IsSigned</code>, even on routes that
don't require sign-in). It builds an <code>auth_service.Group</code> and adds methods
conditionally:</p>
<ol>
<li><code>auth_service.OAuth2{}</code> — only if the request was flagged with <code>AllowOAuth2</code>.</li>
<li><code>auth_service.Basic{}</code> — only if the request was flagged with <code>AllowBasic</code>.</li>
<li><code>auth_service.ReverseProxy{CreateSession: !isSessionless}</code> — only if
   <code>setting.Service.EnableReverseProxyAuth</code>; must run <strong>before</strong> <code>Session</code> per the
   inline comment, otherwise a previously-created session would suppress the
   reverse-proxy header on subsequent requests.</li>
<li><code>auth_service.Session{}</code> — always added; this is what makes normal browser-cookie
   sign-in work, and it's a no-op if the user is already signed in via one of the
   methods above.</li>
<li><code>auth_service.SSPI{CreateSession: !isSessionless}</code> — only on Windows with SSPI
   enabled (<code>auth_model.IsSSPIEnabled</code>), and always added <strong>last</strong>, per its own
   documented constraint.</li>
</ol>
<p><code>isSessionless := allowOAuth2 || allowBasic</code> — non-browser auth methods explicitly
avoid creating a persistent session, since the client is expected to re-authenticate
on every request (e.g. <code>git clone</code> sending Basic auth on each HTTP request).</p>
<p><code>common.AuthShared(ctx.Base, ctx.Session, group)</code> runs the group's <code>Verify()</code> chain,
sets <code>ctx.Data["IsSigned"]</code>, <code>ctx.Data[middleware.ContextDataKeySignedUser]</code>,
<code>ctx.Data["SignedUserID"]</code>, <code>ctx.Data["IsAdmin"]</code>, and returns whether the auth was via
HTTP Basic (<code>ar.IsBasicAuth</code>) so later checks (e.g. rejecting Basic auth for 2FA-enabled
accounts on git-http) can react to it. If auth fails outright it returns
<code>401 Unauthorized</code>; if no credentials were presented at all, <code>ctx.Doer</code> stays <code>nil</code> and
any stale <code>uid</code> is removed from the session.</p>
<h2 id="5-per-route-auth-policy-csrforigin-protection-verifyauthwithoptions">5. Per-route auth policy &amp; CSRF/origin protection (<code>verifyAuthWithOptions</code>)<a href="#5-per-route-auth-policy-csrforigin-protection-verifyauthwithoptions" class="heading-anchor" aria-label="Link">#</a></h2>
<p><code>verifyAuthWithOptions(options *common.VerifyOptions)</code> builds the closure attached to
routes as <code>reqSignIn</code>, <code>reqSignOut</code>, <code>optSignIn</code>, <code>optExploreSignIn</code>, and the
admin-panel's <code>adminReq</code>:</p>
<pre class="highlight"><code class="language-go">type VerifyOptions struct {
    SignInRequired               bool
    SignOutRequired              bool
    AdminRequired                bool
    DisableCrossOriginProtection bool
}</code></pre>
<p>Each generated middleware, in order:</p>
<ol>
<li><strong>Prohibited/inactive account checks</strong> — if the doer is signed in but inactive
   (pending email confirmation) or <code>ProhibitLogin</code>, renders the appropriate notice page
   instead of continuing.</li>
<li><strong>Forced password change</strong> — if <code>ctx.Doer.MustChangePassword</code> and the request isn't
   already for <code>/user/settings/change_password</code>, redirects there (returning <code>401</code> with
   a <code>UserMsg</code> instead, for <code>git</code>-user-agent clients, since a redirect is useless to a
   git client).</li>
<li><strong><code>SignOutRequired</code></strong> — if a signed-in user hits a sign-out-required route (e.g.
   <code>/user/login</code>), redirects them away (honoring an optional <code>redirect_to</code> param).</li>
<li><strong>Cross-origin/CSRF protection</strong> — for any route that is <em>not</em> <code>SignOutRequired</code> and
   has not opted out via <code>DisableCrossOriginProtection</code>, calls Go's standard-library
   <code>http.CrossOriginProtection</code> (<code>crossOriginProtection.Check(ctx.Req)</code>, backed by the
   <code>Sec-Fetch-Site</code> browser fetch-metadata header) and returns <code>403 Forbidden</code> on
   failure. This is Gitea's replacement for a classic CSRF-token cookie/form-field pair
   — see the note in <code>context.Contexter()</code> about the legacy token mechanism having been
   dropped. Non-browser clients (git CLI, RSS readers, OAuth2 non-browser flows) never
   send <code>Sec-Fetch-Site</code>, so those route groups use
   <code>optSignInFromAnyOrigin = verifyAuthWithOptions(&amp;common.VerifyOptions{DisableCrossOriginProtection: true})</code>
   to bypass this check safely (it isn't a cross-origin <em>browser</em> request in the first
   place).</li>
<li><strong><code>SignInRequired</code></strong> — redirects anonymous users to
   <code>middleware.RedirectLinkUserLogin(ctx.Req)</code> (preserving the original URL for
   post-login redirect), or shows the "activate your account" page if the account isn't
   confirmed yet.</li>
<li><strong>Stale "remember me" cookie</strong> — if not signed in but the <code>CookieRememberName</code> site
   cookie is present, redirects to log in (to let the remember-me auth method act on
   it) rather than silently proceeding as anonymous.</li>
<li><strong><code>AdminRequired</code></strong> — returns <code>403 Forbidden</code> if <code>!ctx.Doer.IsAdmin</code>; otherwise sets
   <code>ctx.Data["PageIsAdmin"] = true</code> for the template layout to render the admin nav.</li>
</ol>
<h2 id="6-feature-flag-permission-guards">6. Feature-flag &amp; permission guards<a href="#6-feature-flag-permission-guards" class="heading-anchor" aria-label="Link">#</a></h2>
<p>After the global chain above, individual route groups attach small closures (all
defined inline in <code>registerWebRoutes</code>) as additional per-route/per-group middlewares:</p>
<ul>
<li><strong>Feature flags</strong> (<code>setting.*</code>-driven <code>403</code>/<code>404</code>): <code>webhooksEnabled</code>,
  <code>starsEnabled</code>, <code>lfsServerEnabled</code>, <code>federationEnabled</code>, <code>dlSourceEnabled</code>,
  <code>sitemapEnabled</code>, <code>packagesEnabled</code>, <code>feedEnabled</code>, <code>oauth2Enabled</code>,
  <code>openIDSignInEnabled</code>/<code>openIDSignUpEnabled</code>, <code>reqMilestonesDashboardPageEnabled</code>.</li>
<li><strong>Unit/permission guards</strong>: <code>reqUnitAccess(unitType, accessMode, ignoreGlobal)</code> for
  org/owner-page sections, and <code>context.RequireUnitReader(...)</code>/
  <code>context.RequireUnitWriter(...)</code> (aliased as <code>reqRepoIssuesOrPullsReader</code>,
  <code>reqUnitCodeReader</code>, <code>reqRepoAdmin</code>, etc.) for per-repository-unit checks — these run
  <em>after</em> <code>context.RepoAssignment</code>/<code>context.OrgAssignment</code> have populated
  <code>ctx.Repo</code>/<code>ctx.Org</code> so they can inspect <code>ctx.Repo.Permission</code> or
  <code>ctx.Org.Organization.UnitPermission(...)</code>.</li>
</ul>

  if(overlay){

    document.addEventListener('keydown',function(e){if(e.key==='Escape')overlay.classList.remove('open');});
  }
  // Code copy buttons
  document.querySelectorAll('pre').forEach(function(pre){
    if(pre.classList.contains('mermaid'))return;
    var btn=document.createElement('button');
    btn.className='code-copy';btn.textContent='Copy';
    btn.addEventListener('click',function(){
      var code=pre.querySelector('code');
      var text=code?code.textContent:pre.textContent;
      navigator.clipboard.writeText(text).then(function(){btn.textContent='Copied!';setTimeout(function(){btn.textContent='Copy';},2000);});
    });
    pre.appendChild(btn);
  });
  // Back to top
  var btt=document.getElementById('back-to-top');
  if(btt){
    window.addEventListener('scroll',function(){btt.style.display=window.scrollY>300?'flex':'none';});
    btt.addEventListener('click',function(){window.scrollTo({top:0,behavior:'smooth'});});
  }
  // TOC active scroll tracking
  var tocLinks=document.querySelectorAll('.toc-aside a[data-anchor]');
  if(tocLinks.length>0){
    var headingEls=[];
    tocLinks.forEach(function(l){var el=document.getElementById(l.dataset.anchor);if(el)headingEls.push({el:el,link:l});});
    var tocAside=document.querySelector('.toc-aside');
    var onScroll=function(){
      var scrollPos=window.scrollY+80;
      var active=null;
      for(var i=0;i<headingEls.length;i++){if(headingEls[i].el.offsetTop<=scrollPos)active=headingEls[i];}
      tocLinks.forEach(function(l){l.classList.remove('toc-active');});
      if(active){
        active.link.classList.add('toc-active');
        // Scroll active link into view within the TOC panel, not the page
        if(tocAside){
          var linkTop=active.link.offsetTop-tocAside.offsetTop;
          var visibleTop=tocAside.scrollTop;
          var visibleBottom=visibleTop+tocAside.clientHeight;
          if(linkTop<visibleTop+40||linkTop>visibleBottom-40){
            tocAside.scrollTop=linkTop-tocAside.clientHeight/2;
          }
        }
      }
    };
    window.addEventListener('scroll',onScroll);
    onScroll();
    // Prevent TOC links from scrolling the TOC panel to top on click
    tocLinks.forEach(function(l){
      l.addEventListener('click',function(e){
        e.preventDefault();
        var anchor=l.dataset.anchor;
        var target=document.getElementById(anchor);
        if(target){target.scrollIntoView({behavior:'smooth',block:'start'});}
      });
    });
  }
  // Persist sidebar scroll position across page navigations
  var sidebarEl=document.querySelector('nav.sidebar');
  if(sidebarEl){
    var sidebarKey='sasva-sidebar-scroll';
    // Restore scroll position on page load
    var savedScroll=sessionStorage.getItem(sidebarKey);
    if(savedScroll){sidebarEl.scrollTop=parseInt(savedScroll,10);}
    // Save scroll position before navigating away
    document.querySelectorAll('#sidebar-nav-links a').forEach(function(a){
      a.addEventListener('click',function(){
        sessionStorage.setItem(sidebarKey,String(sidebarEl.scrollTop));
      });
    });
    // Also scroll active item into view on load
    var activeLink=sidebarEl.querySelector('a.active');
    if(activeLink&&!savedScroll){
      var linkOffset=activeLink.offsetTop-sidebarEl.offsetTop;
      sidebarEl.scrollTop=Math.max(0,linkOffset-sidebarEl.clientHeight/2);
    }
  }
})();
</script>
